# Проверка схемы перед сужением блокировок истории поставщика

Историческое объединение карточек поставщика временно блокирует таблицы,
в которых проверяет доступ и старые документы. Прежде чем сужать этот список,
нужно понять, есть ли данные и другие разрешённые писатели в двух таблицах,
для которых код приложения не нашёл активной записи.

Из корня приложения запустить:

```bash
python3 scripts/run_supplier_history_schema_audit.py
```

Команда использует те же настройки `DB_*`, что и приложение. Отчёт показывает
манифест таблиц, наличие и точное число строк в `supplier_offer_assignments` и
`supplier_subscriptions`, их триггеры, права текущей роли и роли PostgreSQL с
правом записи. SQL выполняется внутри транзакции `READ ONLY` и завершается
`ROLLBACK`; данные не изменяются. Время каждого запроса ограничено 15 секундами.

Результат помогает проверить состояние базы, но не доказывает отсутствие
внешнего процесса, который подключается под ролью с правами записи. До отдельной
проверки таких процессов и чтения старых назначений глобальные блокировки
сохраняются.
