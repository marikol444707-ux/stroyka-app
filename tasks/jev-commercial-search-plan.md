# Поиск коммерческих строительных закупок

Запрос пользователя: настроить поиск коммерческих закупок. Начальная область,
озвученная пользователю: строительные, ремонтные и отделочные работы в
Ставропольском крае. Не регистрироваться, не покупать тарифы, не подавать заявки.

Первый адаптер — публичная торговая площадка B2B-Center. Региональный фильтр
без регистрации недоступен; используем доступный поиск по названиям городов,
проверяем регион по карточкам, а ограничение охвата показываем в отчёте.
Не использовать SEO-раздел «Коммерческие» как доказательство: он содержит
контракты и 223-ФЗ/615-ППРФ. Не обходить закрытые фильтры или документы.

Этапы:
- Наблюдать реальный поиск и структуру результата; GET HTML без JS возвращает
  нефильтрованную страницу, поэтому требуется проверка поля и активной вкладки
  после рендеринга браузером.
- Тесты фильтра работ, региона места выполнения, будущего срока по МСК,
  дубликатов ID, ошибки поиска/пустого результата, чужих ссылок.
- Ограниченный одноразовый сбор через отдельный контейнер без ключей/аккаунтов.
- Карточка: заказчик, предмет, место, срок, цена либо «не указана», источник.
  Неизвестный правовой режим или адрес — «Нужно проверить», не готовый заказ.
- Прогон живой цепочки, JSON/HTML отчёт и команда повторного запуска.

Первая версия не покрывает все площадки, все населённые пункты и архивы;
расписание, подписка на письма и регистрация — отдельно после проверки качества.

## Подключение дополнительных площадок

Пользователь запросил расширить поиск за пределы текущего набора. Адаптер ЭТП
ГПБ добавлен в `scripts/jev_commercial_search.py` и проверен на тестовом
сервере без установки: публичный API подтвердил сохранение фильтров активного
приёма и региона Ставропольского края (ID региона площадки — 69). На момент
проверки API вернул 0 активных процедур. Это успешная пустая выдача, а не
ошибка источника; при полном поиске отчёт всё равно явно показывает статус
каждой площадки.

ЭТП ГПБ разделяет типы закупок по категории. Только `Закупки.Бизнес`
классифицируется как коммерческая процедура. `Закупки.Бизнес223` (223-ФЗ) и
`Закупки.Гос44` (44-ФЗ) исключаются. `Торговый портал` и неизвестные значения
не считаются коммерческими автоматически и остаются на ручную проверку.
Ссылка на процедуру должна быть HTTPS-ссылкой с официального домена и
ожидаемым путём.

Сбер А подключён отдельным публичным браузерным адаптером: выбранный источник
«Торги коммерческих заказчиков», поисковая фраза и диапазон даты окончания
подачи (сегодня — 365 дней вперёд) сверяются с отправленным URL и видимым
состоянием страницы. Сайт убирает параметры из адресной строки после загрузки.
Карточки берутся только из этого раздела и только с
официальной ссылкой `utp.sberbank-ast.ru/VIP/NBT/PurchaseView/...`. Типы
«продажа», «реализация» и «аренда» исключаются; неизвестный тип остаётся на
проверку. Регион подтверждается по тексту места выполнения, а не по адресу
заказчика. Проверяются три поисковые фразы на первой странице каждой выдачи;
охват остаётся частичным. Публичные объявления о продаже недвижимости,
встречающиеся в выдаче, не являются закупками и отсекаются.

### Уже подключённые источники

ТЭК-Торг добавлен в общий одноразовый поиск через открытую серверную выдачу
официального [раздела 223-ФЗ и коммерческих закупок](https://www.tektorg.ru/223-fz/procedures).
Проверяются четыре первые страницы по запросам ремонта и строительства в
Ставрополе и ремонта в Невинномысске. Берутся только строки со статусом
«Приём заявок», будущим сроком и строительным предметом. Раздел объединяет
223-ФЗ и коммерческие процедуры, поэтому правовой режим остаётся неизвестным,
а карточки требуют ручной проверки. Регион, найденный только в заголовке,
также не подтверждает адрес работ.

В ограниченной проверке по этим запросам активных совпадений в регионе не
нашлось. Это результат конкретных первых страниц, а не утверждение, что на
всей площадке нет закупок. Пустая выдача засчитывается успешной только при
совпадении поискового URL, секции, статуса и счётчиков результатов.

заказов.

### Критерии подключения каждого источника

- Документировать официальный URL и разрешённый публичный endpoint/страницу.
- Проверять, что запрос сохраняет фильтр активного срока и региона; при
  отсутствии точного фильтра отражать реальный охват, не заявлять полное
  покрытие края.
- Не подтверждать коммерческий режим по слову «коммерческий» в заголовке:
  использовать явный тип/раздел источника, а неизвестный режим отправлять на
  проверку.
- Нормализовать заказчика, предмет, адрес выполнения, срок по МСК, цену и
  оригинальную ссылку. Отделять адрес заказчика от фактического места работ.
- Убирать дубли по устойчивому ID площадки и проверять смену URL/номера.
- Иметь тесты для пустой выдачи, ошибки/редиректа, неверного региона,
  истёкшего срока, 44-ФЗ/223-ФЗ, неизвестного режима и недоверенной ссылки.
- Показывать статус источника независимо: «проверен — есть результаты»,
  «проверен — нет активных результатов», «нужна авторизация/тариф»,
  «недоступен/ошибка». Не скрывать частичный отказ площадки.

Расписание и фоновая подписка остаются отдельным этапом: сначала накопить
проверенные ручные результаты и оценить точность/дубли. Сбор остаётся
публичным, одноразовым и без регистрации, оплаты, скачивания закрытых
документов, связи с заказчиком или подачи заявки.
