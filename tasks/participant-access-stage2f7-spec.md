# 2е7. Закрытие ошибочного доступа к отдельным счетам

Локальный шаг после 2е6. Ни публикации, ни изменения настоящих компаний.

- Новая отдельная операция `revoke_invoice_access`, путь `invoice-access-plans`,
  флаги backend/frontend `PARTICIPANT_INVOICE_ACCESS_CORRECTIONS_ENABLED` по умолчанию 0.
- Использовать прежнее точное подтверждённое подключение, компанию, владельца,
  сроки, версии, журнал, повтор операции и повторную проверку перед применением.
- Разрешить счета без КП только без заявки; накладные — с точной прямой или
  обратной связью с этими счетами, без неоднозначных поставок/заявок.
  Цепочки с КП по-прежнему проверяются целиком. Неясные связи блокируют операцию.
- В компании в `company_supplier_links.profile.closedStandaloneInvoiceIds`
  сохранить точные ID закрытых отдельных счетов. Это серверное поле доступа,
  недоступное для записи обычным редактором карточки. Обычное редактирование и
  повторная активация связи сохраняют список. Статус связи сам по себе не запрет.
  Не добавлять зависимость обычного чтения от таблиц поддержки/новой миграции.
- Общий серверный фильтр счетов всегда учитывает запрет, включая доступ к
  оригиналам и фото связанных накладных. Выключение экспериментальной команды
  не восстанавливает доступ. Новые ID и другие компании запрет не затрагивает.
- Предварительная SELECT-only проекция проверяет фактические политики чтения:
  закрываются ровно указанные документы и оригиналы; независимый доступ блокирует.
- Не менять ни одну строку счёта, КП, поставки, накладной, оплаты или склада.
  Сохранять ID, реквизиты, суммы и статусы. В плане/журнале — только ID/счётчики/
  хеши, никаких финансовых снимков или ссылок на файлы.
- UI показывает список и последствия той же командой, без нового обычного
  бизнес-согласования. Существующие режимы не расширяются без нового флага.

Проверки: отдельный оплаченный счёт+оригинал+накладная, смешанная цепочка,
другая компания/новый счёт, выключение флага, повтор/гонка/откат, изменение
данных после плана, неопределённая заявка/договор/общий оригинал,
сохранение запрета при обычном редактировании. PostgreSQL только изолированный.
