# План внедрения Джева для поиска строительных заказов

## Цель

Сделать Джева полезным в реальном поиске заявок на ремонт, отделку и строительство по Ставропольскому краю: он получает доступ только к разрешённым источникам, находит новые публикации, объясняет, почему они подходят, и передаёт подтверждённые карточки в Стройку. Настройка должна работать повторяемо без ручного разбора ошибок пользователем.

## Текущее состояние

- В проекте есть приём входящих лидов MAX в CRM и другие сценарии MAX, но обнаруженного коннектора для поиска заказов на ЕИС, Poisk-Pro, Profi.ru или Avito нет.
- Предыдущий поиск был сделан обычным веб-поиском, а не Джева и не подключённым браузером. Его нельзя считать доказательством работоспособности Джева.
- Пользователь работает в VS Code на Mac; попытка доступа к Chrome через `node_repl` остановилась на запрете импорта `node:process`. Не повторять этот обход: выбрать поддерживаемый интерфейс браузера.
- У источников разные правила и технические возможности. Публичные открытые данные — основной путь; агент с браузером нужен как исследовательский/резервный канал, а не как обход ограничений площадок.

## Архитектурное решение

Разделить систему на три части:

1. **Доступ Джева к браузеру разработки.** Подключить поддерживаемый browser-control/MCP-инструмент к VS Code/Codex и проверить, что он управляет нужной вкладкой Chrome с понятным пользователю разрешением. Если действующий клиент не предоставляет такой интерфейс, установить поддерживаемый адаптер; не использовать `node_repl` для доступа к процессу Chrome.
2. **Источники и сбор.** На сервере Стройки использовать официальные API, открытые наборы данных, RSS и разрешённые публичные страницы. Браузерная сессия Джева — только для интерактивной проверки открытой страницы и источника, где автоматический API недоступен. Никакого обхода CAPTCHA, авторизации, платного доступа, ограничений частоты или приватности.
3. **Результат в Стройке.** Сначала сохранять находки в очередь «Кандидаты заказов» со ссылкой, источником, датой публикации, регионом, сроком подачи, суммой и фрагментом доказательства. Дубли объединять по стабильному ID/URL и отпечатку текста. Публикацию в основные заявки и любые отклики выполнять только после проверки человеком.

## Этапы и критерии готовности

### Этап 1. Инвентаризация возможностей Джева и браузерного моста

- Зафиксировать точное название/версию агента и где он выполняется (VS Code/Codex, расширение, MCP-сервер).
- Проверить доступный официальный способ управления вкладкой Chrome: открытие URL, чтение видимого текста/DOM, переход по ссылке; не читать cookies, пароли или локальные профили.
- Проверить, что агент работает в обычном запросе без ошибки `node:process` и может вернуть заголовок страницы, URL и короткий фрагмент.
- Если соединение не поддерживается, выдать одну точную инструкцию установки/включения нужного адаптера и повторить тот же smoke-check.

**Критерий:** Джева может открыть публичную страницу и вернуть её URL, заголовок и текст; пользователь не копирует содержимое руками.

### Этап 2. Контракт данных и безопасный импорт

- Определить единый формат находки: `source`, `source_item_id`, `url`, `title`, `description`, `published_at`, `region`, `work_types`, `price`, `deadline`, `evidence`, `collected_at`, `confidence`.
- Добавить валидацию, нормализацию дат/цен/региона и идемпотентность по `source + source_item_id` либо canonical URL.
- Не сохранять лишние персональные данные; телефон/почту хранить только когда это законно и действительно необходимо для работы по заявке.
- Импортировать только в отдельный статус «Нужно проверить», не создавать автоматически заказ/сделку и не выполнять отклик.

**Критерий:** Повторный импорт одного объявления не создаёт дубль; неизвестные поля не ломают импорт; у каждой карточки есть первоисточник.

### Этап 3. Первый вертикальный коннектор: открытые закупки ЕИС

- Выбрать официальный канал открытых данных/выгрузки ЕИС и проверить на тестовом запросе поля, частоту обновления и правила использования.
- Искать по Ставропольскому краю и словарю строительных работ из `tasks/jev-browser-agent-search-terms.md`.
- Отфильтровывать завершённые закупки, будущие планы без опубликованного извещения и закупки только материалов, если целевой профиль — подрядные работы.
- Сохранять ID закупки, редакцию, официальный URL и дату последней проверки статуса.

**Критерий:** тестовый запуск возвращает актуальные закупки, отсекает завершённые, показывает дату/дедлайн и не создаёт дубликаты после повторного запуска.

### Этап 4. Браузерный исследовательский сценарий Джева

- Джева получает ограниченный список разрешённых открытых URL (публичные категории Poisk-Pro/Profi.ru и другие после правовой проверки).
- Он ищет только новые публичные страницы, извлекает ограниченный набор полей и прикладывает цитируемый фрагмент/ссылку.
- При блокировке, входе, CAPTCHA, rate-limit или сомнении в правилах агент останавливает источник и сообщает статус, не пытаясь обходить защиту.
- Результаты сначала выводятся в отчёт/JSON для ручной сверки, затем проходят через общий импорт кандидатов.

**Критерий:** на одном источнике найденные записи открываются по URL, дата и текст подтверждаются страницей; блокировки фиксируются как «источник недоступен», без выдуманных результатов.

### Этап 5. Экран в Стройке и расписание

- Показать очередь кандидатов с фильтрами по компании, региону, виду работ, бюджету, сроку и источнику.
- Добавить действия «Подходит», «Не подходит», «Дубль», «Открыть источник» и журнал причин решения.
- После стабильной работы ручного запуска добавить плановый сбор только для источников, где он разрешён и технически надёжен.
- Уведомлять о новых совпадениях; отклики, сообщения площадкам и подача тендерных заявок остаются ручными действиями.

**Критерий:** директор видит свежие кандидаты и их первоисточники, может быстро отсортировать/отклонить, а повторный запуск не возвращает удалённые пользователем дубли.

## Проверочные точки

1. После Этапа 1: доступ Джева к публичной странице подтверждён настоящим browser-control инструментом.
2. После Этапов 2–3: ЕИС-коннектор выдаёт валидные недублирующиеся кандидаты и корректные сроки.
3. После Этапов 4–5: один браузерный источник проходит сбор → проверку → импорт → отображение в Стройке; повторный запуск безопасен.

## Риски и меры

| Риск | Последствие | Мера |
|---|---|---|
| У Джева нет доступного моста к пользовательскому Chrome | Нельзя использовать уже открытую авторизованную вкладку | Сначала отдельный smoke-check и поддерживаемый MCP/browser adapter; не писать сборщик до подтверждения |
| Изменение разметки сайта | Пропуски или неверные поля | Хранить ссылку и доказательный фрагмент, мониторить ошибки схемы, показывать уверенность |
| CAPTCHA, закрытый/платный контент или запрет автоматизации | Блокировка аккаунта/источника | Остановить автоматический сбор, перейти к официальному API или ручной проверке |
| Старые и повторные объявления | Шум и дубли | Дедупликация по ID/URL и нормализованному отпечатку, статус публикации и даты |
| Смешение закупок и частных заказов | Непригодные лиды | Разные типы источников, фильтры статуса/бюджета/работ, очередь ручной проверки |
| Ложные сроки/цены из агрегатора | Ошибочные коммерческие решения | Для тендера считать юридическим источником ЕИС/ЭТП и сохранять дату сверки |

## Не входит в первую версию

- Автоматическая подача тендерных заявок или откликов на частных площадках.
- Чтение закрытых чатов, аккаунтов или страниц без явного разрешения владельца.
- Обход CAPTCHA, авторизации, платного доступа или технических ограничений площадки.
- Выдача браузерному агенту токенов MAX, паролей или секретов Стройки.
