# Точный объект заявки снабжения

Новые заявки снабжения хранят одновременно неизменяемый `project_id` и название
объекта для отображения. Сервер принимает ID только внутри выбранной компании и
сверяет его с названием. Архивный, чужой или несовпадающий объект отклоняется.

`Основной склад` не является строительным объектом. Для него `project_id` остаётся
пустым, а владельцем служит точная компания заявки.

Для старых заявок используется команда:

```bash
npm run audit:supply-project-ids
```

Она работает только для чтения, откатывает транзакцию и выводит:

- точные строки, готовые к привязке;
- неоднозначные и отсутствующие объекты для ручной проверки;
- количество готовых строк и SHA-256 плана.

Запись разрешена отдельной командой только с точным количеством, SHA предыдущего
dry-run и фразой `APPLY_SUPPLY_REQUEST_PROJECT_IDS`. Перед записью план повторно
строится под блокировкой; изменение данных прекращает операцию. Названия объектов
в отчёт не выводятся.

Выпуск `9d3f674d` применил миграцию `0081_supply_project_id`: пять однозначных старых
заявок привязаны к точным объектам. Четыре записи, для которых объект не найден, оставлены
без изменений до явного сопоставления.
