# Оплаты: подключение к приложению — 28.09.2026

Статус: локальный проверенный этап, без выпуска или активации на сервере.
Финансовый блок целиком не завершён.

## Реализовано

Основное приложение регистрирует HTTP-маршруты реестра с действующими проверками
компании, плательщика, объекта и роли. SUPPLIER_PAYMENTS_ENABLED по умолчанию 0.
Интеграционные тесты больше не подменяют отсутствие регистрации отдельным роутером.

При REACT_APP_SUPPLIER_PAYMENTS_ENABLED=true в счетах снабжения и входящих
документах бухгалтерии появляется «Оплата и история» вместо старой оплаты.
Используется существующая форма точных сумм с сохранённым UUID, повтором,
частичными платежами и сторно. У полностью оплаченного счёта история доступна.
Компания и пользователь передаются явно. Чужая/неопределённая компания блокирует
открытие; смена компании, пользователя или документа закрывает старую форму.
Отключённый флаг сохраняет прежний интерфейс без новых запросов.

## Обязательный следующий этап до активации

Новый тест test_current_release_gate_paid_offer_cannot_ship_until_receipt_integration
подтвердил: после оплаты через реестр POST /supplier-offers/{id}/ship возвращает
409 «Приёмка таких документов пока не поддерживается». Это проверка сохранности,
а не успешный сквозной сценарий.

1. Связать строки неизменяемой спецификации счёта с отдельными отгрузками/приёмками.
2. Зарегистрировать доказанные связи нескольких частичных накладных со счётом
   в той же транзакции, что и приёмка/склад, с повтором без дублей.
3. Использовать реестр распределений для нескольких накладных; не копировать
   всю оплаченную сумму счёта в каждую накладную и не создавать повторный долг.
4. Проверить предоплату, несколько частичных поставок, расхождения, окончательный
   расчёт, сторно, повтор и конкурирующие запросы через main API и браузер.
5. Только после этого включить оба флага и выпустить с проверкой сохранности.

Существующий managed_delivery_receipt рассчитан на одну полную однопозиционную
накладную; не подходит для общего сценария. Защитные запреты ship/receive не сняты.
Рабочие данные, реальные платежи и сервер в этом этапе не изменялись.
