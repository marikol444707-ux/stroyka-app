# Получатель подотчёта в расчёте с исполнителями — 09.11.2026

Статус: исправление подготовлено локально поверх установленного `19df4d3`.
На сервер этот пакет пока не установлен. Миграций и изменений рабочих данных нет.

## Ошибка и исправление

POST `/accountable-payments` проверяет сотрудника выбранной компании и сохраняет
`given_to_id`, однако GET возвращал только имя. Экран «Закрытие исполнителей»
сопоставлял подотчёт с выполненными работами по имени. Один аванс 100 ₽ попадал
сразу к двум сотрудникам с одинаковым именем. После переименования сотрудника
его аванс мог перестать учитываться либо сопоставиться с оставшимся однофамильцем.

GET теперь возвращает сохранённые `givenToId` и `companyId` вместе с прежними
полями. Если `givenToId` присутствует, экран сопоставляет только этот ID со
сотрудником; совпадение имени не может перебить несовпадающий ID. Имя на момент
выдачи сохраняется и не заменяется сегодняшним именем сотрудника.

Суммы, назначение, принадлежность и история платежей не изменяются. Правила
проведения выплат/создания актов и фильтры серверной авторизации не менялись.

## Ограничения

- Исторические записи без givenToId сохраняют прежнее сопоставление. Их
  неоднозначную принадлежность этот пакет автоматически не восстанавливает.
- Один аванс того же сотрудника по нескольким пакетам работ может учитываться
  повторно: распределение между пакетами отдельно не исправлялось. Поэтому весь
  блок зачёта авансов не считается закрытым.
- Подотчёт на материалы и аванс в счёт оплаты труда пока не разделены этим
  исправлением; правила такого зачёта требуют отдельного решения и проверки.
- Сопоставление возмещений, существующих актов и старых выплат по текстовому
  назначению осталось прежним. Серверная изоляция проверена в выбранном HTTP-сценарии,
  полный аудит всех путей расчёта не выполнялся.
- Не проверены отдельные рабочие роли в полном браузере, нагрузка и установка
  данного пакета. Полный запуск на восстановленном резерве нужен перед установкой.
