# P2 — подтверждённая отправка КП

Контракт: PUT /supplier-offers/{id}, action=respond сохраняет существующее КП.
Новый клиент передаёт requestId (UUID) и expectedRespondedAt (null либо версия
из прочитанного КП). Существующие клиенты без этих полей остаются совместимыми.

Повтор того же UUID/пользователя/тела подтверждается без повторной записи и события.
Изменённое тело с прежним UUID отклоняется409. Проверка доступа выполняется заново
после блокировки строк, включая повтор. Уже выбранное/отклонённое КП новой отправкой
не изменяется; точный повтор старой операции возвращает текущее состояние и
submissionAccepted=true. Устаревшая версия формы отклоняется409. Событие хранит
отпечаток тела и идентификатор пользователя в существующем payload_json, без миграции.

Обновление КП выполняется в одной транзакции: прежнее подключение autocommit
делало FOR UPDATE неэффективным. Соединение закрывается и при неожиданном исключении.
После блокировки перечитывается статус, в том числе для существующего отзыва КП.

Интерфейс блокирует форму на время отправки, сохраняет черновик при ошибке,
проверяет подтверждение сохранения, ограничивает ожидание20секундами. Повтор
неизменённой формы использует прежний UUID. Черновик/UUID живут в текущей форме,
не записываются в локальное хранилище. После повторного входа загружаются сохранённые
предложения. Запоздалый ответ после смены пользователя/формы не вызывает действий.
При неопределённом результате автоматической повторной отправки нет.

Счета, оплаты и внешние уведомления не изменяются. PostgreSQL-проверки выполняются
на отдельной временной базе с заблокированными внешними сервисами.
