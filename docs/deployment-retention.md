# Хранение материалов выпуска

Правило пользователя от 20.09.2026: после успешной установки и проверки обновления
удалять резерв предыдущей версии и временные материалы выпуска. Не накапливать
полные копии истории интерфейса и Git на сервере.

- До успешного завершения резерв нужен для отката; не удалять его при ошибке.
- Для резерва интерфейса брать текущие ресурсы из asset-manifest.json и публичные
  файлы, а не весь static с историческими хешами. Старый commit доступен в Git;
  дополнительный полный Git bundle для каждого резерва не нужен.
- Не использовать каталог предыдущего staging как источник следующего резерва:
  завершённые staging удаляются.
- Успешный выпуск создаёт deployed.json с полным head только после проверок
  health/DB, хешей frontend и сохранности данных.
- scripts/finalize_release.py удаляет только завершённые каталоги /root/stroyka-*
  с head-предком текущего здорового runtime. Учитывает deployment-lock и ссылки
  systemd/nginx/cron/работающих процессов. Остаётся лишь маленькая JSON-квитанция.
- Установлены /usr/local/sbin/stroyka-finalize-release и systemd timer/service
  из ops/systemd. Проверка выполняется каждые две минуты; во время выпуска пропуск.

Другие рабочие копии и незавершённые каталоги не объявляются успешными автоматически.

Дополнительное правило: одного deployed.json и health недостаточно. После
проверки backend, базы, хешей frontend и сценария в браузере записать verified.json:
`{"head":"полный SHA выпуска","checks":{"backend":true,"database":true,"frontend":true,"browser":true}}`.
Файл создаётся только по фактическим результатам проверки, не заранее при установке.
Без него, при несовпадении SHA или любой незавершённой проверке резерв сохраняется.
