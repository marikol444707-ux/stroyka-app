Сервер использует `COMPANY_MATERIAL_ALIASES_ENABLED=1`, но общий
`resolve-frontend-build-env.sh` не передавал соответствующий frontend-флаг.

имеет приоритет над backend/.env, отсутствующее значение даёт явный 0,
некорректное блокирует сборку. Секреты и произвольные frontend-переменные не
передаются. HTML содержит режим сборки; verifier проверяет его точное совпадение
и наличие company-owned API в собранном JS. Legacy API не разблокируется.

Тест истории версий теперь получает настоящий `useShellOverlayState`, как
приложение. Сохраняются все 12 сценариев гонок и конфликтов. Три backend hash

изменения относятся к физической приёмке 5301551, пакет warehouse preview и его
регистрация не менялись. Ни одна проверка не отключена; main.py не изменён.

Дополнительно обнаружен устаревший интеграционный тест alias → приёмка: он
отправлял приход без оригинала после введения обязательной документной проверки.

## Установка и ограничения

Выпуск требует пересборки/публикации frontend с новым resolver; одного обновления
тестов недостаточно. Перед публикацией ещё раз сравнить флаги с сервером.
Backend не перезапускать, миграции и изменения рабочих записей не нужны.
Резервировать только текущий frontend manifest, используемые ресурсы и public;
проверить восстановление в отдельный каталог. При сбое восстановить frontend
и предыдущую ветку, не менять базу или режимы backend.

После установки отдельно проверить backend, схему/защиты БД, frontend-хеши и
авторизованный путь «Проекты → объект → Материалы → Соответствия материалов»:
company-owned GET успешен, старый endpoint больше не вызывается. Мутации на
production не нужны: они проверены на отдельной базе. Только после всех четырёх
проверок оформить verified/deployed и очистить стадию по retention.

Не закрывает остальные пункты `remaining-work-2026-11-09.md`: долговечные
складские черновики, новые пакеты прав/платежей, счета, аналитика и кабинеты.
Предыдущие незавершённые выпуски не становятся проверенными автоматически.
