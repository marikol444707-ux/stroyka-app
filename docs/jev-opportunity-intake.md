# Передача результатов поиска JEV в Стройку

JEV ищет закупки на публичных площадках, а Стройка принимает только строки из разделов `confirmed` и `review`. Записи создаются в очереди «Возможности» выбранной организации со статусом «Нужно проверить». Автоматическое подтверждение закупки или создание сметы не выполняется.

## Одноразовая настройка

1. После установки API-изменений задайте на сервере `JEV_OPPORTUNITY_INGEST_KEY`. Он включает интеграцию чтения профилей и приёма отчётов. Ключ — случайная строка не короче 32 символов; один и тот же ключ нужен на сервере и компьютере оператора. Не передавайте его в чате и не помещайте в репозиторий.
2. На Mac добавьте ключ в приложение «Связка ключей»: новый пароль типа «Общий пароль», имя/служба `stroyka-jev-opportunity-ingest`, учётная запись `stroyka26.pro`, пароль — тот же ключ. Скрипт читает его через `security` и не печатает.
3. Убедитесь, что SSH alias `stroyka-dev-agent` доступен без интерактивного пароля и разрешает `sudo -n stroyka-jev commercial-search`.

Если серверный endpoint не настроен, импорт выключен и ответит `503`; локальный скрипт остановится до запуска поиска, если ключ не найден.

## Обычный запуск

Из корня репозитория выполните:

```bash
python3 scripts/jev_commercial_search_and_import.py
```

Скрипт получает профили активных организаций, запускает JEV отдельно для каждой из них по SSH, отправляет отчёт с ID этой же организации и печатает сводку. Поиск выполняется последовательно, чтобы не запускать несколько браузеров одновременно. При необходимости адрес можно переопределить переменной `JEV_OPPORTUNITY_API_URL` (только HTTPS, без пути).

JEV получает профили методом `GET` на тот же endpoint. Ответ содержит только ID организации, регион, поисковые фразы и включённые площадки. Поисковые фразы становятся запросами на B2B-Center, Росэлторге, Сбер А, ТЭК-Торг и Р-ТЕНДЕР; источники с публичной выдачей только по региону сначала возвращают региональные карточки, затем фразы отбирают подходящие. `POST` передаёт ID компании и отчёт для неё; сервер отклоняет несовпадающие ID и проверяет, что JEV всё ещё подключён.

Повторная отправка безопасна: источник и идентификатор объявления (или его каноническая ссылка) образуют ключ дедупликации. Повтор не создаёт вторую карточку и не перезаписывает статус или решение проверяющего. Кандидаты из JEV остаются на ручной проверке.

## Состав передаваемого отчёта

- `confirmed` и `review` импортируются как кандидаты на проверку;
- `excluded` остаётся только в отчёте JEV и в очередь не передаётся;
- без `targetCompanyId` кандидаты распределяются по настройкам каждой организации; с ним отчёт ограничивается этой организацией, и сервер повторно проверяет активность подключения;
- endpoint принимает не более 200 кандидатов и отчёт до 1 МБ.

На очереди «Возможности» видны источник, ссылка, срок и сведения, возвращённые площадкой. Пользователь выбирает дальнейшее действие вручную.

## Подключение и тариф

Администратор платформы настраивает для каждой организации отдельный флаг, ежемесячную стоимость, поисковые фразы и площадки в кабинете платформы. Поле стоимости пока фиксирует тариф в настройках организации: автоматического выставления счёта, списания оплаты или блокировки доступа по неоплате этот блок не выполняет. Перед продажей функции нужно отдельно связать тариф с действующим биллингом и определить период, налоги, льготный доступ и поведение при просрочке.
