# Передача результатов поиска JEV в Стройку

JEV ищет закупки на публичных площадках, а Стройка принимает только строки из разделов `confirmed` и `review`. Записи создаются в очереди «Возможности» выбранной организации со статусом «Нужно проверить». Автоматическое подтверждение закупки или создание сметы не выполняется.

## Одноразовая настройка

1. После установки API-изменений задайте на сервере `JEV_OPPORTUNITY_COMPANY_ID` и `JEV_OPPORTUNITY_INGEST_KEY`. Это фиксирует организацию назначения и включает endpoint. Ключ — случайная строка не короче 32 символов; один и тот же ключ нужен на сервере и компьютере оператора. Не передавайте его в чате и не помещайте в репозиторий.
2. На Mac добавьте ключ в приложение «Связка ключей»: новый пароль типа «Общий пароль», имя/служба `stroyka-jev-opportunity-ingest`, учётная запись `stroyka26.pro`, пароль — тот же ключ. Скрипт читает его через `security` и не печатает.
3. Убедитесь, что SSH alias `stroyka-dev-agent` доступен без интерактивного пароля и разрешает `sudo -n stroyka-jev commercial-search`.
4. На сервере Стройки установите Nginx-маршруты для API и CRM-панели: `python3 scripts/ensure_job_candidates_nginx_route.py /etc/nginx/sites-enabled/stroyka`, затем `nginx -t && systemctl reload nginx`. Скрипт создаёт резервную копию конфига и безопасен при повторном запуске.
5. Проверьте маршруты командой `bash scripts/check-public-api-proxy.sh`. CRM-маршрут должен возвращать `401/403` без сессии, JEV-маршрут — `401/422/503` без ключа/тела; Nginx `405` означает, что location не установлен.

Если серверный endpoint не настроен, импорт выключен и ответит `503`; локальный скрипт остановится до запуска поиска, если ключ не найден.

## Как работает поиск

JEV проверяет первые страницы B2B-Center по 11 видам строительных работ, а также открытые выдачи Росэлторга и Фабриканта. Покрытие неполное; модель не принимает решение вместо пользователя (`model_calls: 0`). Для B2B-Center результаты без признака Ставропольского края отбрасываются, неизвестный объём работ по строительному запросу и неизвестный правовой режим остаются в ручной проверке. Поставки материалов без работ, ремонт производственной/транспортной техники, утилизация отходов и явно другой регион исключаются.

Панель проверки находится в CRM. Запись появляется в организации, закреплённой серверной переменной `JEV_OPPORTUNITY_COMPANY_ID`; для текущей настройки это организация №1. JEV не подтверждает закупку и не создаёт смету автоматически.

## Обычный запуск

Из корня репозитория выполните:

```bash
python3 scripts/jev_commercial_search_and_import.py
```

Скрипт запускает JEV по SSH, передаёт JSON-отчёт в `https://stroyka26.pro/internal/jev/job-candidates` и печатает только сводку импорта. При необходимости адрес можно переопределить переменной `JEV_OPPORTUNITY_API_URL` (только HTTPS, без пути).

Повторная отправка безопасна: источник и идентификатор объявления (или его каноническая ссылка) образуют ключ дедупликации. Повтор не создаёт вторую карточку и не перезаписывает статус или решение проверяющего. Кандидаты из JEV остаются на ручной проверке.

## Состав передаваемого отчёта

- `confirmed` и `review` импортируются как кандидаты на проверку;
- `excluded` остаётся только в отчёте JEV и в очередь не передаётся;
- организация задаётся только серверной конфигурацией, её нельзя выбрать в запросе;
- endpoint принимает не более 200 кандидатов и отчёт до 1 МБ.

На очереди «Возможности» видны источник, ссылка, срок и сведения, возвращённые площадкой. Пользователь выбирает дальнейшее действие вручную.
