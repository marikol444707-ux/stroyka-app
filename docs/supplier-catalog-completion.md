## Контракт

Компания читает и меняет только свою связь `company_supplier_links` с явным
`company_id` и `platform_account_id`. Категория, рейтинг, статус, договор, заметки,
контакты и условия работы принадлежат этой связи. Обновление требует актуальную
`relationshipVersion`; конфликт возвращает 409. Деактивация сохраняет историю.
Создание/изменение связи и audit выполняются одной транзакцией. Ошибка audit
откатывает и новую глобальную карточку. Схема проверяется; HTTP не создаёт её.

Глобальная юридическая карточка сопоставляется только по точному ИНН/ОГРН.
Имя, email, телефон и группы дублей не дают полномочия кабинета. Право поставщика
определяет прямая связь `suppliers.user_id` с активным пользователем роли поставщик.
Регистрация не захватывает существующую организацию по приглашению или совпадению
реквизитов. Для существующей карточки нужна проверка привязки администратором
платформы; автоматическая процедура подтверждения владения здесь не создавалась.
Поставщик не становится сотрудником клиента при регистрации.

Публичные phone/email/specialization, редактируемые самим поставщиком, независимы
от контактов и специализации в карточке конкретной компании. Каталог компании
и подбор **никогда не подставляют публичные значения вместо её приватных полей**.
Публичный endpoint отвергает клиентские договоры, рейтинг и заметки.

Подбор/сравнение проверяют сохранённую компанию заявки, действующее членство,
роль, объект и пакет. История и рейтинг ограничены компанией. Окно КП ничего не
отмечает автоматически; сервер повторно проверяет ровно переданные положительные
целые ID, активную связь и прямую привязку кабинета. Дубли и `aiRecommendedIds`
не расширяют адресатов. Наличие нужного материала не выводится из рейтинга.
Поставщик без привязанного кабинета не может быть адресатом КП; сервер возвращает
объясняющий 409. Каталог сохраняет такие карточки для ведения отношений.

Архив документов поставщика также ограничен компанией (перенесён готовый
изолирующий patch `8d0512a9`, без счетов/оплат, с дополнительным запретом
чтения клиентского архива поставщиком). Старые записи без доказанного
владельца не раздаются клиентам. `0008_supplier_doc_ownership` — единственная
предпосылка каталога после 0007; остальные будущие миграции не запускаются.

Поставки и претензии проверяют согласованную цепочку компания → заявка → КП →
поставка и видимость получателя. Ответ поставщика на скрытую претензию запрещён;
закрытие доступно внутренней роли. Приёмка проверяет компанию до существующего
writer. AI-сверка после задержки повторяет аутентификацию (включая отзыв cookie
сессии), проверяет текущие права и неизменность исходной поставки перед записью.

Подтверждение точного материала сохраняет прежние session/2FA/CSRF, актуальность
исходных данных, явные confirm/revoke и `selectionAllowed=false/sendAllowed=false`.
Ошибки 403/404/409/503 объясняются без внутренних отпечатков. Флаги этого режима
не включаются автоматически: сборка выпуска сохраняет default-off UI. На сервере
backend-флаг `SUPPLIER_MATERIAL_CAPABILITY_RUNTIME_ENABLED=true`; включение UI
остаётся отдельной настройкой после проверки реальных источников сметы.

   не `stamp` и не платежную цепочку. В общей будущей ветке это независимый head

   Повторный запуск не создаёт дублей/audit; чужие новые условия не перезаписывает.
