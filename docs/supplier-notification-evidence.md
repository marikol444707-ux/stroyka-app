# P3.1 — проверка уведомлений и обновление КП

Первый законченный шаг P3: чтение достоверных фактов и обновление экрана заказчика.
Повторная отправка email/MAX и восстановление очереди — отдельный P3.2; этот шаг
не отправляет сообщения и не исправляет исторические строки автоматически.

Read-only аудит сервера b48eff7d от2026-09-19:12получателей; все email отмечены
«Пропущено: тестовый email». У6получателей MAX не привязан, у6сохранена отметка
«В очереди MAX» и номер очереди, но соответствующей доступной записи нет.
Отметка в получателе не является доказательством постановки в действующую очередь.

Контракт GET /supply-requests/{id}/recipients расширен полями:
- maxQueueEvidence: matched / unconfirmed / not_requested;
- maxFailedAttempts: счётчик НЕУДАЧНЫХ попыток (dispatcher увеличивает его только
  при исключении); maxFailedAt, maxSentAt, maxQueueUpdatedAt, maxQueueCreatedAt.
Все поля фактов null, если ссылка не подтверждена. Join требует совпадения
company,user,request,provider,event,entity,owner_scope=company, как у MAX-worker.
Наличие только старой отметки очереди без ID также даёт unknown/unconfirmed.
Raw provider errors, идентификаторы чатов и содержимое сообщения не выдаются.
Дата updated_at не называется датой попытки; failed.next_attempt_at не обещает
автоматический повтор, поскольку текущий worker выбирает только queued.

Кнопка «Обновить КП и уведомления» читает пары offers/recipients без записи.
Новая цена/срок/комментарий отражаются прямо в карточке, без перезагрузки страницы.
HTTP-ошибка/неверный JSON не превращаются в пустой успешный результат: ошибка
остаётся на экране, старые кнопки выбора скрываются. Лимит ожидания20секунд.
Смена пользователя/компании/заявки и размонтирование отбрасывают запоздавший ответ.
После общего обновления supplierOffers локальный снимок уступает новым props.

Тесты: RED на отсутствующие факты очереди и обновление карточки; unit/RTL;
реальная PostgreSQL/HTTP проверка scoped evidence, запретов чужим пользователям,
неподтверждённых ссылок на другую компанию/пользователя/owner_scope и отсутствия
изменений offers/recipients/outbox после чтения. Статус: проверка перед выпуском.
