## Исправлено

Обычный каталог компаний теперь подтверждает объединение по серверному отпечатку
просмотренных карточек и документов, а не только версиям связей. В отпечаток входят
компания/account, полные заблокированные карточки и связи, а также содержимое
исходных счетов, складских накладных и предложений. Изменение суммы, состава,
ИНН, имени или банка требует нового просмотра. Документы удерживаются FOR SHARE
до конца транзакции; чужие карточки и операции с кабинетом сохраняют прежние запреты.
Миграций нет. Оригинальные документы, supplier_id и оплаченные суммы не переписываются.

В интерфейсе только подтверждённые сервером взаимные связи одной компании
объединяются в основную строку. Имя/ИНН сами по себе не объединяют строки.
Исходные ID используются для истории; поля редактирования/рейтинг/версия берутся
из основной карточки. Смена компании закрывает старую карточку и диалог; поздний
ответ не открывает их и не запускает обновление старого списка. Результат без
серверного отпечатка не допускает подтверждения. Отказ 409 сохраняет выбор,
автоматического повторного объединения нет.

Дополнительная подтверждённая ошибка: два разных документа с одинаковыми печатными
полями скрывались как дубли. В каталоге компании теперь исключается только повтор
того же ID. Существующий учёт счёта, связанного со складской накладной, сохраняется.

## Установка и совместимость

Backend/frontend обновляются согласованно; новых зависимостей/миграций нет, схема
0107_estimate_revisions. Старый клиент без expectedReview получает 409 с указанием
сохранить черновики и обновить страницу; запись запрещена, принудительной перезагрузки
нет. Перед ручным обновлением старой вкладки отдельно сохраняют несохранённые черновики. Уже открытая
старая вкладка продолжает использовать старый код, и сама установка этого не исправит.

Выпуск: точная база/чистое дерево → серверные проверки → сборка с фактическими
флагами → свежий резерв текущего manifest/public и БД при остановленных writers →
проверка восстановления в отдельную БД → backend и frontend → health/схема/хеши/
контрольные таблицы/службы → отдельный браузер. Production-карточки не объединяются
для тестирования. Без авторизованного production-сценария не создавать verified.json
или deployed.json; резерв остаётся до фактической проверки по deployment-retention.md.

Откат под deployment-lock/обслуживанием: вернуть backend 269757132c97 и текущие
файлы из rollback/frontend, восстановить прежние состояния служб и проверить
health/схему/файлы. База совместима, откат схемы не нужен. Дамп автоматически поверх
новых пользовательских операций не восстанавливать. Старый backend снова содержит
ошибку подтверждения; после отката объединения требуют повторной проверки.

## Ограничения и оставшееся

Полная интеграция admin complete-INN и изменения административного duplicate_merge
из PR #374 в этот пакет не входят. Уже существующий путь открытия истории кабинету
не изменён и не объявляется заново принятым. Другие модули/складской PR #372 не
переносились. Охвачены три типа документов обычного merge; одновременный writer
фактически проверен для supplier_invoices, не для каждого writer всех таблиц.
Нагрузочный прогон больших архивов, полный браузер всех ролей/тем, печать и файлы,
глобальная уникальность всех записей поставщиков и внешние уведомления не проверялись.
Авторизованный production-браузер по-прежнему требует обычной пользовательской
сессии; публичный вход и локальная приёмка его не заменяют. GitHub не публикуется.
