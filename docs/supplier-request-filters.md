# P5 — поиск, фильтры, страницы и CSV поставщика

Реестр использует полные авторизованные массивы из useSupplierInbox: запрос
supply-requests без limit не ограничен, supplier-offers также возвращает весь
доступный список. Новый endpoint не нужен. Пагинация по 20 строк применяется
после поиска/фильтров; число найденных и CSV используют все совпадения.

Общая проекция supplierRegistryQuery определяет материалы из itemsJson/items,
реальное название заказчика, первую корректную requestedAt и состояния всех КП
по заявке. Строка существует только при наличии и request, и offer. Список
заказчиков/статусов строится из этих же строк. Неизвестные состояния сохраняются.

Поиск: номер (также с №), материалы, объект; Unicode NFKC, регистр не важен,
ё/е эквивалентны. Заказчик и состояние КП пересекаются с поиском. Если у заявки
несколько КП, фильтр состояния совпадает при наличии такого КП. Изменение фильтра
и сброс возвращают первую страницу; уменьшение выборки ограничивает номер страницы.

CSV выгружает текущий загруженный снимок, все отфильтрованные строки, а не страницу.
UTF-8 BOM, разделитель ;, все ячейки в кавычках, кавычки удваиваются; переносы внутри
ячеек сохраняются. Формулы с = + - @, включая префиксы пробелов/управляющих символов
и полную ширину, предваряются апострофом. Временный Blob URL освобождается.
При загрузке/ошибке исходный inbox скрывает реестр, выгрузка устаревшего снимка
не предлагается. Проверка прав и изоляция запросов остаются серверными.

Проверки: RED перед реализацией; 4 целевых suites/26 tests PASS; полный frontend
188 suites/1170 tests PASS. Backend и схема не менялись. Сборка и browser QA ниже.

Ограничение: фильтрация клиентская, как существующая загрузка полного inbox.
При существенном росте объёма понадобится серверная фильтрация с общими count/export
контрактами; переход к частичной загрузке без изменения P5 недопустим.

## Browser QA и ревью

На отдельной синтетической PostgreSQL-базе: 25 видимых заявок двух заказчиков,
ещё одна скрыта. Проверены страницы 20+5, поиск ЕЛКА→ёлка вне первой страницы,
пересечение заказчика/состояния, пустой результат, сброс. Реально скачанный CSV
разобран csv.reader: 12 строк выбранной компании, 6 колонок, скрытой заявки нет.
Другой supplier: 0 строк, CSV disabled. Desktop1440 и mobile320 просмотрены;
ширина документа320. Production build PASS. Baseline: фоновый GET
company-material-aliases получает403 для supplier, preload facade warning;
новых ошибок JavaScript не обнаружено. Эти общие загрузчики не менялись.

Ревью корректности, доступа, структуры и производительности: одна проекция
таблицы/экспорта, без дополнительных источников данных или изменения прав;
фильтрация до slice, memo по снимку/фильтрам. Данные, счета и оплаты не менялись.
