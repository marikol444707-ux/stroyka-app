# P4 — реестр адресных заявок поставщика

Заменить заглушку единственного заказчика и длинный первоначальный список форм
реестром по доступным серверным requests/offers. Одна строка на requestId; реальные
заказчик, объект, материалы, дата запроса КП (requestedAt), состояния предложений.
Дата создания заявки не выдаётся за время получения КП. Неизвестные значения
показываются явно. Сроки/срочность/менеджер не выдумываются: P5/P6/P9 отдельно.

Desktop: боковая навигация и таблица; mobile: горизонтальная навигация и карточки.
Открытие строки выбирает заявку и сохраняет supplyRequestId в URL. После reload
или перехода Назад/Вперёд выбирается только доступная заявка. Если она исчезла,
показать отсутствие доступа без старых форм. Формы ответа, счета и отгрузки
остаются существующими; финансы не меняются.

GET supply-requests для роли поставщика дополняется companyName из companies
только для уже отобранных доступных companyId. Без нового общего списка компаний.

Проверки: группировка повторных предложений, неизвестные статусы, заказчик из
scoped API, отсутствие чужих данных, URL/reload, ошибка/загрузка, мобильный320.

- Полный backend: 3787 tests, OK, 651 skipped (интеграционные сценарии требуют

- Независимое ревью: исправлено сохранение видимой формы после возврата к списку.
  Черновик теперь скрывается и восстанавливается при повторном открытии заявки.
- Настоящий браузер на синтетической PostgreSQL-базе: заказчик и материалы из API,
  открытие заявки, reload, возврат к списку, Назад/Вперёд. Mobile 320px без
  горизонтального переполнения документа. Выполнены desktop/mobile screenshots.
- В браузере также замечен 403 фонового company-material-aliases для supplier:
  это отдельный общий загрузчик, права не расширялись; реестр загружается успешно.
  Сохраняется исходное предупреждение preload изображения посадочной страницы.
