# Распределение позиций между поставщиками

При запросе КП заказчик отмечает материалы отдельно для каждого поставщика.
Одну позицию можно запросить у нескольких поставщиков для сравнения. Поставщику
показываются только назначенные позиции; сервер проверяет состав и количество ответа.
Срок ответа по умолчанию остаётся следующим будним днём по Москве.

Директор выбирает позиции полученного КП. Каждая позиция заказывается один раз,
включая одновременные попытки утверждения. Остальные КП остаются доступны, пока
в них есть ещё не заказанные позиции. Утверждённый состав фиксируется; дополнения
оформляются отдельной заявкой. История ответа сохраняет первоначальное полное КП.

Счёт, отгрузка и статус заказа поставщика рассчитываются по утверждённому составу.
Общая заявка закрывается только после приёмки всех её исходных позиций. Частичная
поставка одного из поставщиков не закрывает оставшуюся потребность.

API: `POST /supply-requests/{id}/request-kp` принимает `supplierItems` — объект
с ID выбранных поставщиков и массивами индексов исходных позиций (от нуля).
`PUT /supplier-offers/{id}` с `action: select` принимает `itemPositions`.
Ответы КП содержат `requestedItemsJson` и `awardedItemsJson`.
Без `supplierItems` сохраняется прежний сценарий КП на всю заявку; смешанное
утверждение старого КП на весь состав и распределённых КП отклоняется.

Миграция 0051 добавляет два nullable TEXT-поля без изменения старых записей.
Откат кода допускает сохранение этих полей; downgrade запрещён при сохранённых
назначениях, чтобы не потерять состав заказов.

Проверки: изолированный PostgreSQL — разделение состава, запрет лишних позиций,
изоляция доступа, конкурирующее утверждение, счёт, раздельные отгрузки и приёмка.
Отдельно проверено создание спецификации счёта с бухгалтерским реестром и
сохранением исходных номеров позиций. Интерфейс проверяется компонентными тестами
и в локальном браузере на вымышленных данных без реальных писем.
