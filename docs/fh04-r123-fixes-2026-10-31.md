## Изменения

R1: payment-specific loadAll выполняет строгий GET supplier-invoices с выбранной
компанией. HTTP/JSON/сетевая ошибка отклоняет Promise; пустой fallback запрещён.
Проверяются точный invoice/company и оплаченная сумма не ниже подтверждённой
операцией. Только после актуального ответа обновляется supplierInvoices и
возвращается квитанция requestId/companyId/invoiceId. Панель проверяет квитанцию
перед очисткой active pending. Обычный loadAll остальных компонентов не изменён.
Отказ refresh сохраняет UUID и сообщает, что запись оплаты подтверждена,
а обновление списка — нет. Проверка суммы здесь относится к отображению,
а не заменяет серверную идентичность операции или денежные вычисления.

R2: чтение/выбор/сохранение/отправка команды защищены Web Locks с ifAvailable.
Если API отсутствует, занят или отклоняет запрос, операция не отправляется;
небезопасного fallback нет. До отправки тело записывается в отдельный immutable
по соглашению ключ attempt:<UUID>; несовпадающее тело никогда не перезаписывается.
Active key остаётся совместим с ранее сохранённым pending. После подтверждения
удаляется только active key под тем же lock, запись попытки сохраняется.
Одна вкладка не перезаписывает UUID другой при соблюдении нового протокола.
Web Locks не объявляется доступным в каждом браузере. Это координация вкладок
одного origin/хранилища, не замена серверной идемпотентности и не lock устройств.
Старые открытые вкладки с предыдущим кодом не участвуют в новом протоколе:
при будущей приёмке/выпуске необходима проверка обновления клиентской версии.
Записи попыток остаются в локальном хранилище данного профиля, автоматическая
очистка истории или восстановление после удаления browser storage не добавлялись.

R3: lifecycle generation инвалидируется при смене пользователя/компании/loading
и при unmount. Проверки стоят до отправки после lock grant, после ответа,
перед применением refresh, перед очисткой pending и перед UI feedback.
Logout/уход со страницы не отменяет уже начатую серверную транзакцию и не стирает
UUID. Поздний callback не запускает refresh/очистку после инвалидирования.

Backend, миграция 0109, flags, суммы, финансовые guards и правила оплаты не менялись.
