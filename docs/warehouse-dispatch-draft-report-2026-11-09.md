## Ошибка и результат

Обновление общей истории распределений, применение фильтра и ошибка GET
сбрасывали выбранное распределение и уничтожали заполненную форму отправки.
Открытие другой отправки или приёмки также стирало её без подтверждения.
Пять регрессионных тестов воспроизвели эти ошибки до изменения кода.

| Действие | Результат после исправления |
| --- | --- |
| Заполнить отправку → обновить общую историю | Объект назначения, количество и основание сохранены |
| Получить новый остаток 2 вместо 15 при введённых 10 | Ввод сохранён, отправка 10 запрещена; показан свежий максимум 2 |
| Фильтр исключил выбранное распределение | Форма остаётся; новая отправка запрещена до успешной загрузки исходного распределения |
| Ошибка загрузки 503 | Форма остаётся редактируемой, доступны отмена и обновление; отправка запрещена |
| Выбрать другую отправку или приёмку | Переход заблокирован до завершения или явной отмены формы |
| Ответ POST 409 | Ввод сохранён, успех не показан, автоматического повтора нет |
| Потерян ответ POST, после обновления распределения нет | Разрешён безопасный повтор старой команды с прежними ID и телом; новая команда запрещена |
| Сменить компанию/права или получить 401/403 | Старый черновик скрывается; поздняя история не восстанавливает его |
| Старый GET завершился после нового фильтра | Не возвращает старый остаток и не разрешает отправку |
| Обновить → подтвердить отправку | Один POST с исходным allocationId, выбранным объектом и введённым количеством; после успеха форма закрывается |

Изменён только срок жизни формы и проверка доступности её источника.
Серверная `warehouse_distribution.transfers.dispatch` по-прежнему проверяет
компанию, блокирует источник и получателя, проверяет остаток, фиксирует
перемещение транзакционно и обслуживает повтор по прежнему requestId.
Это проверено чтением кода; новые серверные проверки здесь не добавлялись.

## Ограничения и установка

- Неотправленный черновик хранится в памяти открытой панели. Полное обновление
  страницы, закрытие вкладки и уход из раздела могут уничтожить его.
  Постоянное сохранение таких черновиков не добавлялось.
- Проверка черновиков возврата и прочих складских форм в этот блок не входит.
  Самостоятельная актуальность списка объектов назначения также не расширялась;
  окончательные права и доступность получателя проверяет существующий backend.
- Предыдущая авторизованная браузерная приёмка серверного пакета `5301551`
  всё ещё не подтверждена. Известные блокеры описаны в
  `warehouse-receipt-report.md`: Chrome runtime не импортирует `node:process`,
  внешний изолированный браузер получил `ERR_TIMED_OUT`. В этой задаче они не
  переобъявлены исправленными. Резервы/staging и маркеры завершения не менялись.
- `warehouse-dispatch-draft.patch` — только этот блок поверх `abe1cb2`.
  Для установленной базы `5301551` подготовлен **единый**
  `warehouse-transfer-drafts.patch`, включающий предыдущий блок приёмки и
  нынешний блок отправки. Эти два варианта нельзя накладывать друг на друга.
- Установка требует сборки frontend с действующими серверными feature flags;
  backend и схема остаются прежними. После публикации проверить manifest и
  файлы, backend/схему без изменения данных, затем обе формы в авторизованном
  браузере. Рабочую тестовую отправку не проводить: проверить ввод, обновление,
  фильтры и отмену. Сквозное проведение допускается только на отдельной тестовой БД.
- Откат только frontend по сохранённым manifest/public текущего выпуска;
  миграция и восстановление БД не требуются. Очистка резервов — только после
  всех четырёх подтверждений по `docs/deployment-retention.md`.
