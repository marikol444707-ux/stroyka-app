# Разбор документов закупки

Рабочая первая версия для отдельного сервера Jev. Не часть production backend.

## Запуск

```bash
sudo stroyka-jev eis-review --notice 'https://zakupki.gov.ru/epz/order/notice/zk20/view/common-info.html?regNumber=0121300045726000245'
```

Принимаются наблюдавшиеся карточки 44-ФЗ `zk20`, `ea20`, `ok20` на точном
HTTPS-домене ЕИС и с одним 19-значным номером. URL оригиналов получаются из
видимых ссылок раздела документов; ссылки сайта/футера и скрытые файлы не входят
в набор. Поддерживается только проверенный публичный filestore ЕИС.

Для каждого запуска создаётся отдельный snapshot в
`/var/lib/stroyka-jev-tools/document-reviews/<номер>/`. Сохраняются оригиналы,
URL, дата, название, SHA-256, текст карточки и снимок перечня файлов. После
скачивания список и текст редакции проверяются повторно. Сменившийся набор
остаётся явной ошибкой полноты, а не успешной проверкой текущей редакции.

## Чтение и отчёт

- DOCX: основной текст, таблицы как абзацы, колонтитулы, сноски; встроенные
  растровые изображения через OCR. Номер абзаца не выдаётся за номер страницы Word.
- XLSX/XLSM: значения и адреса лист/ячейка, без макросов и внешних связей.
- PDF: текст с номерами страниц; страницы без текста — Poppler и Tesseract rus/eng.
- DOC/RTF: antiword/unrtf, источники привязаны к строкам.
- ZIP/RAR/7z: ограниченная рекурсивная обработка без сохранения путей участников.
  Неизвестные и зашифрованные форматы остаются непрочитанными.

Лимиты: до 25 оригиналов; 32 MiB на файл, 128 MiB на загрузку; до 96 MiB
развёрнутого содержимого на исходный архив и глубина до двух вложений; ограничения
числа элементов, текста, PDF-страниц и диапазонов Excel. Выход за лимит виден в
отчёте. Размеры таблиц допускают реальные широкие сметы, но ограничены объёмом.

`report.html` адаптирован для телефона; `report.md` — текстовая версия.
`review.json` хранит извлечение и источники. У каждого вывода есть оригинал и
страница/абзац/лист с ячейкой. ИИ получает ограниченную подборку фрагментов;
в исходных документах может быть дополнительный контекст. Выводы без точной
цитаты, с чужой категорией или выдуманными числовыми условиями отбрасываются.
Наличие цитаты не доказывает безошибочность её толкования: отчёт предварительный.

Нормальные неполные случаи не скрываются: ошибка файла, OCR, неподдержанная
формула, недоступный ИИ, изменившаяся редакция или отклонённый вывод. Оригиналы
и извлечённые фрагменты доступны даже без ИИ-пояснения.

## Границы проверки

Это сбор и предварительный разбор условий, а не допуск к участию, юридическое
заключение или полная сметная экспертиза. Профиль компании не предоставлен;
возможность участия всегда явно помечена как непроверенная.

Простые Excel-формулы SUM/ROUND и арифметика проверяются кодом на Decimal,
если есть числовые исходные и сохранённый результат. Другие формулы, отсутствующий
кэш, ставки/нормативы, разные единицы и НДС не объявляются проверенными.
В двух живых сметах формул не было: чтение готовых чисел не равно их пересчёту.
Согласование условий между документами пока опирается на отобранные фрагменты,
а не на полный структурный анализ всех требований и всех строк сметы.

## Изоляция и установка

Сбор — отдельный одноразовый browser-контейнер без ключей и application cookies.
Разбор файлов — контейнер с `--network none`, без capabilities, с read-only root,
лимитами памяти и временным tmpfs. Документы не становятся командами/инструментами.
Хост получает только структурированные данные. Секрет модели остаётся внутри
существующего `stroyka-jev-control`: в контейнер передаётся текст через stdin.
Новая модель только для документов задаётся `DOCUMENT_REVIEW_MODEL`; существующая
настройка Jev не изменяется. Старая текстовая модель отвечала HTTP 410; для этого
обработчика отдельно проверена `openai/gpt-4.1-mini` через прежний Timeweb endpoint.

`sudo python3 scripts/install_jev_document_runtime.py` разрешён только на
`stroyka-dev-agent.local`: проверяет точный базовый образ, собирает слой парсеров,
запускает тесты без сети и атомарно сохраняет pinned image/model в root-only
`documents-runtime.json`. В релиз копируются только перечисленные в manifest
файлы; ни `.git`, ни `.env`, ни личные профили не монтируются.

Откат — возврат ссылки tools/current к предыдущему проверенному релизу.
Миграций БД и изменений приложения нет. До приёмки предыдущий релиз сохраняется.

## Проверено

Две публичные закупки: №0121300045726000245 и №0321100019426000088.
По пять оригиналов в каждой; во второй проект контракта в RAR и ТЗ в DOC.
Полная цепочка от загрузки до отчёта прошла в отдельном контуре. Дополнительно
проверены текстовый и сканированный PDF, широкая таблица, Decimal-арифметика,
отсутствующий кэш формул, XML entities, выход из архива, сжатая бомба,
подмена оригинала, неизвестная цитата/категория/число и HTML-экранирование.
