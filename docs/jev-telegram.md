# Поиск заказов: отделка, ремонт и строительство домов

Поиск также включает строительство домов и коттеджей, фундаменты, кладку,
кровельные работы и каркасные дома. Реклама строительства и продажа готовых
домов отсеиваются теми же правилами, что реклама ремонтных услуг и продажа
материалов; смешанные сообщения могут требовать ручного просмотра.

Подготовлен отдельный инструмент Jev. В приложение «Стройка» и его базу данных
изменения не вносились. Пользователь выбрал «Строительство Ставрополь»
(пригласительная ссылка) и «Стройка СТАВ» (`rabotastav026`). Авторизации нет,
автоматический мониторинг не включён; история настоящих групп не прочитана.

## Что получается

В приватной HTML-подборке две группы: «Вероятные заказы» и «Нужно посмотреть».
В каждой карточке полный текст сообщения, источник, дата и ссылка на оригинал.
Реклама ремонтных услуг и продажа материалов отфильтровываются по отдельным
правилам. Классификация ориентировочная: короткие и смешанные объявления могут
ошибочно попасть в другую группу. Нельзя считать подборку полным списком заказов.

Точные текстовые повторы сгруппированы и внутри порции, и между запусками,
все оригинальные ссылки сохранены. Регистр, лишние пробелы и совместимые
Unicode-символы не создают дубль. Изменённые цены, контакты и объёмы остаются
отдельными карточками. Семантически похожие тексты не объединяются.
Короткие одинаковые объявления от разных заказчиков тоже могут оказаться
одной группой: это группировка текста, а не доказательство единого заказчика;
все исходные ссылки остаются доступными.

Каждая карточка помечена «Новое объявление» или «Уже встречалось». Новая ссылка
с прежним текстом не увеличивает число новых заказов. Последний отчёт содержит
всю сохраняемую историю данного каталога, включая ранее выбранные источники,
а счётчики исключённой рекламы относятся только к текущей порции.
Для разных аккаунтов/владельцев обязательны отдельные каталоги состояния.
Редактирование/удаление старых сообщений не отслеживается. География пока
определяется выбором чатов; текстового регионального фильтра нет.

## Обработка выгрузки без подключения аккаунта

Для стандартной JSON-выгрузки **одного** Telegram Desktop чата:

```bash
python3 scripts/jev_telegram.py \
  --export /private/path/result.json \
  --source exact_channel_username \
  --output "$HOME/.cache/stroyka-telegram/digest"
```

`--source` — проверенный username исходного канала либо его числовой ID с
префиксом `-100`. Для закрытого источника ссылки открываются только у участников.
Отчёт локальный, не опубликован в интернете. Каталог отчёта должен иметь права
700, файлы получают 600. Объём JSON ограничен 32 MiB и 100000 сообщениями.
Повторные выгрузки обрабатывать с тем же `--output`: история хранится там в
`history.sqlite3`, а HTML/JSON каждой проверки — в отдельной папке `digest-*`.
Путь к готовому отчёту и количество новых карточек печатаются в результате.
Файл `history.sqlite3` не передавать в git или другим владельцам.

## Подготовленный сбор новых сообщений

Зависимость изолированного окружения: `Telethon==1.45.0`.
Приватный JSON-конфиг (600) вне репозитория:

```json
{
  "api_id": 0,
  "api_hash": "REPLACE_LOCALLY",
  "sources": [
    {"id": -1001234567890, "username": "approved_channel", "label": "Выбранный чат"}
  ]
}
```

Это пример, не реальные реквизиты/источник. API ID/hash получают через
[my.telegram.org](https://core.telegram.org/api/obtaining_api_id).
Нужна предварительная интерактивная авторизация через Telethon в отдельном
окружении; логин-коды и пароль вводят локально, не в чат. Готовая сессия
`account.session` находится в приватном каталоге состояния (700, файл 600).
Сессия даёт доступ к аккаунту: не передавать её в Jev/ИИ-контейнер, git,
скриншоты, логи или публичные отчёты. Использовать отдельный аккаунт для
мониторинга предпочтительнее личного.

```bash
python3 scripts/jev_telegram_collect.py \
  --config "$HOME/.config/stroyka-telegram/config.json" \
  --state "$HOME/.local/share/stroyka-telegram"
```

Скрипт не авторизует автоматически, не вступает в чаты, не перечисляет диалоги,
не отправляет сообщения и не скачивает вложения. Публичный username разрешается
в точный числовой ID, несовпадение блокирует источник. Для закрытого источника
его entity должен быть доступен в предварительно подготовленной сессии.

Первое чтение — сообщения за последние 7 дней, следующие — после сохранённого
ID. До 100 сообщений на источник за запуск, до 20 источников, общий лимит
сбора 50 секунд. Порции читаются от старых к новым, поэтому заполненная порция
не пропускает оставшийся хвост. Сводка предупреждает, если требуется дочитать.
При ошибке checkpoint соответствующего источника сохраняется прежним.
При ограничении Telegram возвращается `retry_after`: новый запуск не раньше
указанного числа секунд. Самостоятельного таймера/повторных попыток нет.

Каждый запуск сохраняет отдельную подборку. Карточки в SQLite удаляются через
30 дней после последнего обнаружения при очередной успешной обработке.
Это не срок актуальности заказа. Предел истории — 5000 карточек и 50000 ссылок;
при переполнении обработка явно завершается ошибкой, свежие данные не удаляются,
checkpoint не продвигается. Старые файлы отчётов пока сохраняются; их очистку
нужно настроить до постоянного мониторинга.

SQLite хранит историю и checkpoint одной транзакцией. Если запись отчёта
не удалась, транзакция откатывается и незавершённый отчёт удаляется. Старый
`cursor.json` импортируется в первую успешную транзакцию; далее источник истины
— SQLite. Старые уже созданные отчёты автоматически не импортируются.

## Ограничения и следующий шаг

Нужны работающее подключение к выбранным чатам и авторизация. Затем
проверить качество на настоящих сообщениях и настроить периодичность и хранение.
Эта подготовка протестирована офлайн, а не на действующем аккаунте Telegram.

ИИ и загрузка вложений по умолчанию отсутствуют. Использование данных Telegram
в ИИ требует отдельного согласия соответствующих пользователей по
[правилам платформы](https://telegram.org/tos/content-licensing).

Техническая основа: [история сообщений](https://core.telegram.org/method/messages.getHistory),
[порционное чтение Telethon](https://docs.telethon.dev/en/stable/modules/client.html#telethon.client.messages.MessageMethods.iter_messages),
[хранение сессии](https://docs.telethon.dev/en/stable/concepts/sessions.html).

Проверка: `python3 -m unittest scripts.test_jev_telegram scripts.test_jev_telegram_history -v`.
