# Прямые коммерческие строительные заказы JEV

Требования пользователя от 30.10.2026. Этот режим отличается от установленного
v2-поиска строительных закупок Ставрополья. Изменения не установлены на сервер.
Существующие компоненты допуска дополнены явно передаваемыми защищёнными bindings;
их поведение по умолчанию остаётся v2-only. Ключи, данные, Telegram-регистрация,
File Bridge и расписание на сервере не менялись. Название площадки в реестре
не является доказательством подключения.

## Профиль и правила отбора

- География **работ**: Ставропольский и Краснодарский края; адрес заказчика не
  заменяет подтверждённые регион и адрес объекта.
- Основной список: капремонт зданий/помещений, комплексное проектирование + ремонт.
  Текущий ремонт и модернизация инженерных систем — отдельная категория.
- Ориентир 3 млн рублей; неизвестный бюджет требует уточнения. Валюта не
  конвертируется без курса/источника; НДС не вычисляется по догадке.
- Нужен конечный заказчик или оператор с подтверждёнными полномочиями.
  Предложения субподряда от генподрядчика исключаются.
- 44-ФЗ, 223-ФЗ и 615-ПП не выдаются за прямые коммерческие закупки.
- Приоритет: подтверждённые условия аванса, материалы заказчика или понятная
  поэтапная оплата. Постоплата отдельно, без выдуманного расчёта кассового разрыва.
- ООО/ИП выбирается явно в защищённом профиле. Строительная СРО, проектная СРО и
  лицензия МЧС проверяются независимо; наличие одной не подтверждает остальные.
- Только чтение источников. Запись локального реестра разрешена самой задачей;
  отправка писем, заявок, регистрация, вход в аккаунты, оплата, установка сервера
  и изменение расписания в этот режим не входят.

## Что реализовано

Код: `jev_agent/tender_finder/commercial/`.

1. **model.py**: типизированные первичные карточки/документы и факты. Факт требует
   точной цитаты из захваченного текста, названия документа, ссылки, пункта/страницы,
   времени проверки и SHA256 редакции. Цитата не доказывает правильность смыслового
   извлечения: это обязанность проверенного парсера конкретного источника.
2. **sources.py**: расширяемый каталог 22 направлений, включая Tender.Pro, Ozon,
   девять агрохолдингов, санатории, производство и логистику. Группы официальных
   сайтов — исследовательские направления, не фиктивные подключённые площадки.
   Домены новых заказчиков не угадываются; их добавляет оператор после проверки.
3. **policy.py**: детерминированный отбор, прямой договор, регион работ, стоимость,
   статус, дедлайн, оплата и независимые требования к юрлицу. Противоречивые условия
   остаются видимыми и отправляют находку в неподтверждённые. Новый этап первичной
   карточки имеет приоритет перед старым сниппетом агрегатора.
4. **readers.py**: подключаемый адаптер «план → публичная выдача → первичная
   карточка → парсер». До чтения проверяется разрешённый домен; подмена карточки
   парсером/редиректом отклоняется. CAPTCHA/вход останавливают источник. Транспорт
   должен быть отдельно проверенным GET-only reader без cookies/аккаунтов,
   с тайм-аутом, ограничением тела, robots и проверкой каждого сетевого перехода.
   Здесь нет транспорта по умолчанию или обхода сетевых ограничений.
5. **registry.py**: отдельный от v2 реестр на компанию и владельца, блокировка,
   атомарная запись, права 0700/0600, защита от симлинков и смешения компаний.
   Первый сбор не объявляет всё новым. Изменения сохраняют старое/новое значение,
   источник, редакцию и дату обнаружения. Отсутствие доступа не означает закрытие
   или удаление цены. Межсайтовые дубли объединяются только при подтверждённых
   идентификаторах процедуры, контрагента и объекта; сходства названия недостаточно.
6. **runner.py**: один ограниченный запуск, фактический охват источников, категории,
   счётчики просмотренных карточек и документов, текстовый отчёт с подтверждениями.
   Повтор request_id возвращает прежний отчёт; после аварийного прерывания поиск
   молча не повторяется. Старые записи не удаляются при недоступности источников.
7. **__main__.py**: локальная оценка экспортированных доказательств. Явно сообщает
   `search_executed: false` и `independent_source_verification: false`.
8. **contract.py / bridge.py / preview.py / tool.py**: строгий контракт версии 3,
   необязательная сборка защищённого broker/gateway, подписанный допуск владельца,
   файловая очередь, квитанция выполнения, публикация отчёта/события и ограниченное
   превью для существующего отправителя Hermes. Новый инструмент имеет отдельное
   имя `jev_direct_commercial_search`; никакой автоматической регистрации нет.
   Компания/получатель/юрлицо/квалификации/адреса читателей не принимаются из JSON.
   В реестре namespace протокола 3 не может присвоить namespace протокола 2.
9. **b2b.py / b2b_browser.py**: первый предметный читатель B2B-Center. Использует
   существующие проверенные генератор поискового URL, проверки вкладок и семейство
   ссылок процедур. Запрашивает виды работ и названия двух регионов, повторно читает
   каждую уникальную первичную карточку. В адресе работ ищет явно указанный регион;
   регион организатора не используется. Номер сверяется по URL и тексту карточки.
   Цена/валюта/НДС извлекаются отдельно, часовой пояс не подставляется, противоречащие
   поля не выбираются молча. Организатор и слово «заказчик» не подтверждают прямой
   договор: этот читатель не выставляет role/authority. Таких находок в основном
   списке не будет до отдельного доказательства роли и полномочий.

   Браузерный адаптер использует только Page.navigate и фиксированные чтения
   Runtime.evaluate в предоставленном оператором изолированном браузере без учётных
   записей. Сам браузер здесь не запускается. Ожидается стабильная страница с тем же
   URL; редирект, CAPTCHA, запрос входа, переполнение или тайм-аут прекращают чтение.
   Лимиты: до 20 запросов поиска, до 40 чтений за запуск; тайм-аут одного чтения
   25 секунд. Через 180 секунд новые чтения не начинаются; текущее ограничено своим
   тайм-аутом. Подмена JS/URL/браузерной фабрики из запроса невозможна.

   Статус всегда **partial**: просмотрены первые страницы, документы не прочитаны,
   парсер ещё не сопоставлен с живой разметкой сайта. Тестовые страницы синтетические,
   это не доказательство успешной проверки B2B-Center. Прочитанная, но не разобранная
   карточка учитывается в счётчике чтений; поля закупки из неё не подтверждаются.

## Интерфейс подключения к защищённому worker

```python
from jev_agent.tender_finder.commercial.runner import run
from jev_agent.tender_finder.commercial.model import Profile

# Все bindings задаёт код сервера, а не JSON/модель/текст сайта.
report = run(request_id, authenticated_scope, private_commercial_directory,
             sources=reviewed_sources, adapters=reviewed_public_adapters,
             profile=Profile(legal_entity=selected_entity,
                             qualifications=confirmed_qualifications))
```

Каталог должен быть отдельно подготовлен оператором как приватный. Нельзя
указывать каталоги v1/v2, `.seen`, requests/results либо существующую базу CRM.
Не допускается fallback на компанию 1 или автора последнего Telegram-сообщения.

Результаты источника: `checked`, `partial`, `unavailable`, `login_required`,
`captcha`, `error`; неподключённый источник — `not_connected`. Без свежей выдачи
нельзя заявить полный охват или «ничего не найдено». При смешанных результатах
успешные находки сохраняются вместе с явными ограничениями других источников.

Захваченный текст — недоверенные данные, а не инструкции. Импорт произвольного
JSON от LLM не равен проверке реального первоисточника. Ключи, команды и адресат
Telegram никогда не поступают из такого текста.

## Что ещё не является готовым подключением

- Существующий нативный CLI на сервере закреплён хешами и работает по старой
  географии. Он не превращается автоматически в новый режим.
- Для каждой площадки нужны актуальная публичная точка поиска, проверенный
  GET-only транспорт, парсер первичной карточки и парсеры условий/договора.
  Обобщённый PublicAdapter и предметный B2BReader с браузерной фабрикой уже есть;
  **проверенных вживую и установленных bindings к 22 направлениям нет**.
- Для сайтов агрохолдингов/Ozon/Tender.Pro требуется подтвердить домены, публичные
  разделы и доступность. В каталоге это намеренно не выдумано.
- Просмотр PDF/Office-документов, установление полномочий оператора и смысловое
  извлечение условий требуют отдельных проверенных читателей/парсеров. Нынешний
  PublicAdapter читает карточки; дополнительные документы подаёт другой адаптер
  через Document/Fact, сохраняя привязку к реальным захватам.
- Подключение нового режима к authenticated broker/очереди/публикации Telegram
  реализовано как явная сборка CommercialBridge; необходима отдельная защищённая
  конфигурация протокола 3, каталоги и регистрация в startup. Установленный v2 не
  принимает эти данные. Нельзя просто включить version=3 в старом запросе.
- В этой среде сетевой список доступа не включает закупочные сайты. Живой поиск,
  авторизация, активные процедуры и Telegram-доставка этим изменением не проверены.
- Сохранение реестра ограничено общими 2 МиБ на файл и 1000 идентификаторами
  запусков. При достижении лимита требуется явное архивирование/перенос; код не
  удаляет историю автоматически и не теряет квитанции ради освобождения места.

## Приёмка перед установкой

1. На каждой подключаемой площадке: публичный поиск, карточка и доказательства
   региона работ, прямого контрагента, этапа, срока, оплаты. Счётчики совпадают с
   фактическими чтениями; CAPTCHA/нет доступа не становятся пустой выдачей.
2. Реальные контрольные случаи: Краснодарский край; неизвестная цена; субподряд;
   оператор без полномочий; противоречие карточки и договора; перенесённый дедлайн;
   аванс под гарантию; постоплата; одинаковая процедура на разных сайтах.
3. Повторный сбор с сохранённым реестром: нет ложных новых закупок, есть изменения
   и подтверждения. Сбой/повтор запроса не запускает поиск заново автоматически.
4. Отдельная компания/другой Telegram-владелец не читают и не изменяют реестр.
5. Только после связки с защищённым worker проверить реальный ответ владельцу в
   Telegram. Локальный тест/CI не является доказательством такой доставки.

Локальный тест:

```bash
python3 -B -m unittest -v jev_agent.tender_finder.commercial.test_commercial
python3 -B -m unittest -v jev_agent.tender_finder.commercial.test_bridge
python3 -B -m unittest -v jev_agent.tender_finder.commercial.test_b2b jev_agent.tender_finder.commercial.test_b2b_browser
```

Оценка заранее подготовленного экспортированного bundle (без сетевых запросов):

```bash
python3 -B -m jev_agent.tender_finder.commercial evaluate < evidence-bundle.json
```

Bundle: `format: 3`, `candidates: [...]`; кандидат содержит `source`, `number`,
`documents`, `facts`. Форматы строго соответствуют Document/Fact в model.py.
Все контрольные тесты используют синтетические закупки и не доказывают охват сайтов.

## Запрос версии 3

```json
{
  "version": 3,
  "mode": "direct_commercial",
  "request_id": "commercial-run-001",
  "regions": ["Ставропольский край", "Краснодарский край"],
  "source_ids": ["b2b", "fabrikant"],
  "minimum_rub": "3000000",
  "queries": ["капитальный ремонт", "кровля"],
  "exclude_keywords": []
}
```

Все поля кроме version/mode/request_id необязательны. Источники по умолчанию —
операторский реестр; незадействованные читатели показываются как not_connected.
Цена — строка/целое, без float и дробных копеек. company_id, Telegram ID,
юрлицо, квалификации, URL, команды и ключи в запросе запрещены.

CommercialBridge принимает BridgeSettings с PipelineConfig(protocol=3) и отдельный
пустой приватный каталог коммерческого реестра. Обычный parse_settings загружает
старые настройки и не активирует v3. Подключение на сервере требует отдельной
проверки startup-конфигурации, прав, peer PID и маршрута ответа. Подписание остаётся
на host broker; gateway не получает ключ. Методы submit в тестах моделируют уже
авторизованный host ingress, а реальный Unix listener обязан проверять SO_PEERCRED.

## Пример операторской привязки B2B (не команда установки)

```python
from jev_agent.tender_finder.commercial.b2b_browser import browser_adapter

adapters = {
    'b2b': browser_adapter(open_browser=reviewed_public_browser, clock=aware_clock),
}
```

reviewed_public_browser — защищённая async context manager, возвращающая уже
проверенный ограниченный CDP call. Фабрика отвечает за изоляцию, сетевые ограничения,
robots/access policy, отсутствие credentials и освобождение ресурсов. Нельзя брать
её из модели, произвольного пути или environment fallback. В новой конфигурации
CommercialBridge передаётся этот adapters; остальные источники остаются явно
not_connected. Перед подключением требуется живая read-only сверка реальных
карточек, полей и работы браузера на сервере. Нельзя заменять её флагом verified=True.
