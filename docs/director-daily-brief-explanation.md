# Объяснение и доставка директорской сводки

## Цель

Добавить к готовой детерминированной директорской сводке короткое понятное
объяснение и безопасную доставку в приложение и MAX. Модель не вычисляет суммы,
статусы или приоритеты и не изменяет бизнес-данные.

## Контракт

1. `director.daily_brief` остаётся единственным источником фактов и продолжает
   завершаться независимо от доступности модели.
2. Объяснение создаётся отдельным заданием для точного `company_id` и точного
   завершённого `source_job_id`. Повтор для той же пары идемпотентен.
3. В модель через capability `director_agent` передаётся только публичная,
   уже проверенная и ограниченная схема сводки. Секреты, контакты и произвольные
   данные других компаний в запрос не попадают.
4. Ответ модели считается недоверенным. Сервер принимает только JSON с
   фиксированными полями: заголовок, обзор и не более пяти пояснений. Текст
   ограничен по длине; HTML, команды и новые числовые факты запрещены.
5. Ошибка, таймаут или некорректный ответ модели не меняют исходную сводку и не
   скрывают её в приложении. Интерфейс показывает детерминированные данные без
   AI-пояснения.
6. В приложение объяснение возвращается только руководителю выбранной компании
   вместе с точным `source_job_id` и временем создания.
7. MAX-доставка создаётся отдельно, только для активной привязанной учётной
   записи руководителя этой компании. Одно объяснение доставляется адресату не
   более одного раза; повтор использует тот же ключ идемпотентности.
8. Сообщение содержит ссылку на сводку и ограниченный текст объяснения. Оно не
   содержит кнопок оплаты, списания, перемещения, утверждения или иных команд.

## Этапы

- A4.3a: чистый контракт входа/выхода объяснения и RED/GREEN тесты — завершён.
- A4.3b: отдельный gateway-backed handler и идемпотентный producer, выключенные
  по умолчанию.
- A4.4: чтение объяснения в текущем leadership API и компактный блок интерфейса.
- A4.5: идемпотентный MAX outbox для явно привязанного руководителя.
- A4.6: полный regression/security review, production canary одной компании и
  наблюдение стоимости/ошибок без автоматического fan-out.

## Готовность

- Сбой модели не влияет на доступность исходной сводки.
- Cross-company чтение, постановка задания и доставка запрещены сервером.
- Один источник не создаёт дубликаты объяснений или MAX-сообщений.
- Модель не имеет доступа к БД и не может инициировать бизнес-действие.
- Focused/full tests, production build, браузерная проверка и отдельный canary
  проходят до включения расписания доставки.
