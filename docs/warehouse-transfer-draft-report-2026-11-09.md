## Подтверждённая ошибка и исправление

В действующей двухэтапной форме перемещений обновление списка, поиск и
ошибка GET уничтожали открытую форму приёмки: количество, основание и
подтверждение пользователя терялись. Нажатие приёмки другой карточки тоже
заменяло форму. Родительская панель не знала о незавершённом вводе.

Теперь выбранная карточка с формой остаётся смонтированной до явной отмены,
подтверждённого сохранения или прекращения доступа. Пока карточка не найдена
в успешно загруженных данных, отправка запрещена. Свежий ответ обновляет
остаток в пути и допустимое количество, сохраняя введённые значения.
Открытая приёмка блокирует конкурирующую выдачу/возврат/отправку в общей панели.
Сообщение пользователю прямо указывает, что черновик находится в открытой форме.

| Действие | Проверенный результат |
| --- | --- |
| Заполнить приёмку → обновить список | Ввод и подтверждение сохранены; во время GET отправка запрещена |
| Остаток уменьшился с 10 до 2 | Старое введённое количество 5 остаётся видимым, отправить его нельзя |
| Поиск исключил выбранное перемещение | Черновик остаётся видимым, отправка запрещена; очистка поиска и успешная загрузка восстанавливают доступность |
| GET завершился ошибкой 500/503 | Черновик доступен для исправления или отмены, отправка запрещена |
| Приёмка другой карточки / конкурирующая складская операция | Недоступны до завершения или отмены текущей формы |
| Обновить общую панель распределения | Дочерняя форма приёмки сохраняет ввод |
| Получить 403 / сменить компанию или режим прав | Старые данные и форма скрываются; поздний ответ их не возвращает |
| Потерять ответ POST → обновить → повторить | Сохраняются исходный идентификатор команды и точное тело безопасного повтора |
| Обновить → подтвердить приёмку | Один POST к исходному ID перемещения с сохранёнными значениями; после успеха форма закрывается |

## Ограничения и установка

- Это сохранность ввода при обновлении списка внутри открытой панели.
  Полная перезагрузка страницы, закрытие вкладки или уход из раздела по-прежнему
  могут уничтожить ещё не отправленный черновик. Постоянное хранилище таких
  черновиков не добавлялось. Уже отправленные неподтверждённые команды по-прежнему
  используют существующее хранилище безопасного повтора.
- Старая форма одноступенчатых `warehouse-movements` не менялась. При включённом
  новом режиме она скрыта; серверный журнал качества блокирует старую запись.
- Проверены существующие ограничения интерфейса по ролям и компании, но новая
  полная проверка авторизации API и всей навигации приложения не выполнялась.
- Этот пакет **на сервер не установлен**. Для предыдущего выпуска в отчёте
  `warehouse-receipt-report.md` остаётся незавершённая проверка браузера под
  авторизованным пользователем. Подтверждения её успеха нет; резервные копии
  и стадии не удалять, `verified.json`/`deployed.json` не создавать.
  Зафиксированный блокер инструмента Chrome: импорт `node:process`
  запрещён в `node_repl`; внешний изолированный браузер не открыл сайт
  (`ERR_TIMED_OUT`). Локальная проверка выше этого блокера не закрывает.
- При установке этого отдельного исправления достаточно пересобрать и
  опубликовать frontend с **действующими серверными feature flags**. Backend
  остаётся на совместимой версии; миграции и изменения рабочих данных не нужны.
  Использовать текущую процедуру публикации и хранения резервных копий.
- После установки проверить версию/backend, состояние схемы без её изменения,
  manifest/файлы frontend и форму в авторизованном браузере. Для smoke-проверки
  не проводить фиктивную приёмку: заполнить тестовый ввод, обновить/поискать,
  проверить сохранность и отменить форму. Полное проведение проверять только
  на отдельной тестовой базе.
- Откат — возврат предыдущего frontend manifest и актуальных public-файлов
  по инструкции хранения релизов; БД и backend откатывать не требуется.
