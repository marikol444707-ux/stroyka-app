# Поставщики и объединение дублей: локальное исправление

## Результат

- ИНН/ОГРН сравниваются канонически: разрешены ASCII-цифры, форматирующие
  пробелы и дефисы; неверная длина, буквы и прочая пунктуация отклоняются.
  Регистрация, профиль и заполнение ИНН используют согласованный порядок
  блокировок юридических ключей, затем карточек. Исторические снимки не изменены.
- Старое адресное приглашение и точное совпадение юридического ключа архивной
  карточки разрешаются в основную карточку только внутри подтверждённых компании
  и аккаунта. Цепочки, циклы, неоднозначность, чужие/недоступные цели отклоняются.
  Совпадение названия не даёт права на историю. Повторное приглашение не создаёт
  второй кабинет.
- В снабжении подтверждённая группа отображается одной основной карточкой с
  исходными ID для истории. Совпадения имени/ИНН сами по себе не объединяют строки.
  Открытая карточка переходит на основную после обновления; смена компании
  сбрасывает карточку и диалог. Документы без supplierId не приписываются по имени.
- Старый company-merge flow требует серверный отпечаток preview, связывающий
  компании, карточки, версии и содержимое исходных документов. Изменение данных
  требует нового подтверждения. Присоединение к зарегистрированному кабинету
  этим старым flow по-прежнему запрещено.
- Установщик восстанавливает BEFORE только до запуска target runtime, без
  уничтожения локальных файлов. После возможного запуска нового backend оставляет
  совместимый с закрытием доступов TARGET и явно требует ручного восстановления.
  Проверяет весь manifest, включая lazy chunks. Пишет installed-pending.json,
  но не выдаёт установку за браузерную приёмку и не разрешает очистку резервов.
