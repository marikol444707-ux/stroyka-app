# Agent Execution Contract

## Цель

До запуска отдельного AI-runner зафиксировать машинно-проверяемую границу между
очередью `agent_jobs`, бизнес-данными и моделью. Неизвестное задание или
инструмент должны отклоняться, а не получать доступ по умолчанию.

## Первый безопасный контракт

- Тип задания: `director.daily_brief`.
- Режим: только чтение.
- Модель не получает соединение с PostgreSQL, SQL или произвольный вызов кода.
- Разрешены только существующие tenant-scoped инструменты помощника директора:
  `projects`, `warehouse`, `supply`, `estimates`, `finances`, `staff`,
  `ai_tasks`.
- Tenant context (`company_id`, роли и права) остаётся на стороне сервера и не
  передаётся модели как способ выбрать область данных.
- Подготовленный запуск привязан ровно к одному положительному `company_id` из
  захваченной строки очереди; списки компаний и `all_companies` запрещены.
- В модель можно передать только дату сводки, отображаемое имя компании,
  запрошенные разделы и подготовленные сервером факты. Дата и объект `facts`
  обязательны; разделы и ключи фактов могут ссылаться только на явно выбранные
  read-инструменты.
- Результат каждого инструмента проходит отдельную схему: лишние поля
  отбрасываются, контейнеры/типы/размеры проверяются. Например, внутренний
  `companyId` финансового инструмента в модель не попадает.
- Секреты, сырой SQL/DB-контекст, неизвестные поля и пакет больше 32 KiB
  отклоняются до вызова модели.
- Один запуск ограничен 45 секундами, двумя обращениями к модели, семью
  инструментами, 1600 выходными токенами и бюджетом 500 копеек.

Лимит стоимости является внутренним верхним пределом, а не описанием тарифа
провайдера. Отдельный runner обязан остановить запуск до превышения любого
лимита.

## Границы шага A2.1

Этот шаг не создаёт runner, не вызывает модель, не меняет HTTP-маршруты и не
пишет в сметы, склад, снабжение, назначения или бухгалтерию. Текущий
`/director-agent/ask` продолжает работать как раньше до отдельной миграции.

## Проверка

```bash
python3 -m unittest backend.features.agent_execution.test_contract
python3 -m unittest backend.features.director_agent.test_tenant_scope
python3 -m unittest discover -s backend -p 'test*.py'
```

Успех: registry содержит только известные job types, набор инструментов совпадает
с реальным read-only registry, payload канонизируется и fail-closed проверки
срабатывают до model/provider слоя.
