# Ускорение входного контроля материалов

Пользователь продолжил работу после выпуска `25374a33`: запрос входного
контроля занимал 9,65–11,57 с в авторизованном браузере. Цель — убрать
измеренную причину задержки, сохранив результаты и правила заполнения.

## Измерение и изменение

На свежей закрытой копии шести таблиц production обнаружено 6165 повторных
`ALTER TABLE ... ADD COLUMN IF NOT EXISTS` за один проход входного контроля.
Проверка девяти колонок выполнялась не только перед заполнением, но и внутри
помощника для каждой исходной строки. Кабельный журнал выполнял 504 ALTER.

Теперь backfill передаёт помощникам строк факт успешной подготовки схемы.
Он действует только в текущем вызове и не кэширует ни данные, ни состояние
других подключений. Если подготовка не удалась, проверка в помощниках
сохраняется. Самостоятельные вызовы при приёмке поставок и накладных по-прежнему
проверяют схему. Отбор, параметры SELECT/INSERT, права и данные не изменены.

На одном компьютере, одинаковой копии и PostgreSQL с включённым fsync:

| Показатель | До | После |
| --- | --- | --- |
| Входной контроль, время прохода | 2,02–2,11 с | 0,53–0,58 с |
| Входной контроль, ALTER | 6165 | 9 |
| Входной контроль, SELECT | 1966 | 1966 |
| Кабельный журнал, время прохода | 0,240–0,241 с | 0,103–0,113 с |
| Кабельный журнал, ALTER | 504 | 9 |
| Кабельный журнал, SELECT | 76 | 76 |

В обоих проходах восстановлено 0 записей. Хеши всех шести таблиц совпали:
340 записей входного контроля, 19 кабельных записей, 52 накладные, 515 движений,
298 остатков; таблица поставок пуста. Это локальные замеры, отдельно от
последующей проверки времени HTTP-запросов на production.

## Проверка

Регрессии используют настоящий изолированный PostgreSQL. На исходном коде
оба теста ограниченной работы со схемой упали: 585 ALTER при обработке 64
записей из четырёх источников. На исправлении выполнено не более 9 ALTER,
при этом все 64 записи добавлены, повтор не добавляет строк. Отдельно
проверены недостающие колонки в массовом и самостоятельном вызовах и повторная
подготовка схемы после неуспешной первой попытки.

Просмотр runtime-diff: новый внутренний параметр по умолчанию сохраняет
прежнюю проверку; только две функции backfill передают успешный результат
подготовки. Все восемь путей источников покрыты. Нет новых SQL-запросов,
зависимостей, feature flags, изменений frontend или схемы. Три теста с хешем
всего `main.py` обновлены после просмотра diff; код рекомендаций не изменён.

Артефакты: `output/journal-performance/` (не входят в git). Копия бизнес-данных
хранится вне репозитория в закрытом временном каталоге и удаляется после проверки.
