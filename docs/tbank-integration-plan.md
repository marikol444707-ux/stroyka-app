# План внедрения: интеграция Т-Банк (T-API) как платформенная функция

Дата: 2026-07-28. Статус: проект плана, ждёт «строй» от владельца.
Источники: developer.tbank.ru (выписка `GET /openapi/api/v1/statement`, вебхук «Операция по счету», выплаты самозанятым, песочница без токена).

## 1. Идея в одну фразу

Каждая компания на платформе СтройКа подключает свой расчётный счёт Т-Банка (токен «только выписки»), и деньги перестают расходиться с документами: оплаты актов, счетов и проводки по объектам сверяются с банком автоматически.

## 2. Какие боли закрываем, по ролям

**Бухгалтер:**
- ручной ввод проводок по объектам → автопроводки из выписки с точной датой/суммой;
- «оплачен или нет» по счетам поставщиков и актам исполнителей → статус ставит банк, а не память;
- подотчёт и «мои траты» → сверка с реальными списаниями;
- чеки НПД самозанятых (этап 3) → собираются через API, а не в мессенджерах.

**Руководитель (директор компании):**
- достоверная картина «деньги vs документы» по каждому объекту (кассовый разрыв виден сразу);
- «неопознанные» платежи не теряются — попадают в очередь на разметку;
- статус «Оплачен» на акте больше нельзя поставить словами.

**Снабженец / прораб:** видит, что счёт поставщика реально оплачен — предметный разговор об отгрузке.

**Владелец платформы (system_owner):** банковская синхронизация — платная фича тарифа; в кабинете платформы — здоровье подключений по компаниям (подключено/ошибка/дата последней сверки), без доступа к содержимому чужих операций.

## 3. Как ложится в структуру платформы

- **Подключение — на уровне компании**, в настройках компании (директор): номер счёта + токен T-API (write-only поле: ввести можно, прочитать назад нельзя). Не в кабинете владельца платформы — банк принадлежит компании.
- Новый модуль `backend/features/bank_sync/` по нашему конвейеру (register-модуль, deps, тесты).
- Схема (аддитивная, в стиле `CREATE TABLE IF NOT EXISTS`):
  - `company_bank_connections` (company_id, bank='tbank', account_number, token_encrypted, scopes, status, last_sync_at, webhook_secret);
  - `bank_operations` (company_id, operation_id UNIQUE — идемпотентность по OperationId банка, date, amount, direction, counterparty_name, counterparty_inn, purpose, raw_json, match_status, matched_entity_type, matched_entity_id).
- **Сверка (matching) — только внутри company_id** (правила M6): по ИНН из карточек поставщиков и реквизитов исполнителей; по маркерам в назначении («акт #», «счёт №»); по сумме+дате. Несовпавшие — экран «Банковские операции: на разметку».
- Автопроводки в `project_payments` со ссылкой на bank operation_id (как brigade_payments ссылаются на project_payment_id).
- Вебхук `/bank/tbank/webhook` — не забыть location в живом nginx (урок 2026-07-28) и проверку подписи банка.

## 4. Безопасность

- Токен — только скоуп «Счета и выписки» (не может платить). Хранение: шифрование app-ключом из `backend/.env`, доступ только серверный, в API-ответы не попадает никогда.
- Платёжные поручения (этап 4) — отдельное решение владельца, отдельный токен, отдельный разговор.
- Песочница T-API — без токена и сертификата: этапы 0–1 строятся вообще без реального банка.

## 5. График внедрения (срезами конвейера)

| Неделя | Срез | Результат |
|---|---|---|
| 1 | Песочница: модуль bank_sync, схема, клиент T-API, тесты | работает на тестовых данных, прод не тронут |
| 2 | Подключение компании: форма в настройках, ручная кнопка «загрузить выписку» | директор подключает счёт, операции видны |
| 3 | Matching v1 + экран разметки + автопроводки | бухгалтер перестаёт вбивать проводки |
| 4 | Вебхуки (real-time) + автостатусы актов/счетов + строка «банк» на дашборде объекта | статусы живут сами |
| 5+ | Этап 3: чеки самозанятых. Этап 4 (отдельное «да»): платёжки | по мере готовности |

Каждый срез — полный конвейер: тесты → CI → деплой → смоук → запись здесь. Миграции схемы аддитивные, но любой шаг, трогающий БД, — с явного подтверждения владельца.

## 6. Что нужно от владельца для боевого этапа (после песочницы)

1. Подтвердить: компания обслуживается в Т-Банке (нужен ЛК Т-Бизнеса).
2. В ЛК Т-Бизнеса выпустить токен с правом «Счета и выписки» (+сертификат по их инструкции).
3. Ввести токен в форму настроек компании (не в чат, не в переписку).

## 7. Риски и честные оговорки

- T-API доступен клиентам Т-Бизнеса; для компаний платформы с другими банками — фича недоступна (в будущем — адаптеры других банков поверх той же схемы `bank_operations`).
- Данные выписки в API — с июня 2023; более старую историю не подтянуть.
- Матчинг никогда не будет стопроцентным — очередь ручной разметки это норма, а не сбой.
