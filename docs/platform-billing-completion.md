## Инварианты текущего среза

- Ручное зачисление фиксирует только подтверждённый платёж, положительную конечную
  сумму в рублях с точностью до копейки и серверного автора.
- UUID команды обязателен: повтор той же нормализованной команды возвращает тот же
  платёж; тот же UUID с иным содержимым даёт конфликт. Старые платежи не получают
  выдуманных UUID; новая nullable-схема не меняет их значения.
- Новый период не сокращает уже оплаченный срок. Исторический платёж не открывает
  просроченный доступ. Административное отключение компании не снимается платежом.
- Два подтверждения разных событий одного счёта сериализуются на счёте. Только
  доверенное успешное событие точного владельца/валюты/суммы может закрыть счёт.
- UI сохраняет UUID и данные при неизвестном результате запроса, показывает ошибку
  и допускает безопасный повтор, сбрасывает форму только после подтверждения.

## Договорный срез и защищённые PDF

- Реальные транзакции в записи профиля лицензиара, создании/переходах/файлах
  договора и создании/изменении/подготовке/файлах счетов. Ошибка аудита откатывает
  DB-изменение; профиль сериализуется по аккаунту, документы — по своему ID.
- Закрытый/аннулированный счёт нельзя открыть или перенести на другой договор.
  Платёж провайдера также сохраняет договор оплаченного счёта. Это защищает обе
  стороны сводки от ложного долга/переплаты. UI показывает зафиксированные ссылки.
- Узкое чтение platform staff относится только к canonical protected URL, явно
  привязанному к договору/счёту той же компании и аккаунта. Обычные файлы компаний
  не получают исключения; generic DELETE финансовых вложений запрещён.
