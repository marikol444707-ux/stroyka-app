# Автоматические проверки после изменений

## Что получает пользователь

После активации новой версии сметы система сама ставит в очередь обновление
директорской сводки. Пользователю не нужно запускать проверку вручную. Операция
со сметой завершается независимо от очереди: временная ошибка проверки не
отменяет уже сохранённое изменение.

На экране сметы постоянно видны только действия, нужные для текущей работы:
возврат, проблемы, просмотр и назначение работ. История, Excel, смена статуса,
сверка, шаблоны и анализ находятся в меню «Ещё».

## Как это работает

1. Смета сначала сохраняется и активируется обычной транзакцией.
2. Только после успешного сохранения создаётся одно задание для той же компании.
3. Отдельный обработчик читает данные этой компании и строит детерминированную
   сводку.
4. Повтор одного и того же события не создаёт второе задание.
5. Результат доступен в сводке и очереди внимания; финансовые и складские
   документы не меняются.

Первая разрешённая связь ограничена событием
`estimate.version_activated -> director.daily_brief`. Другие события не
подставляются автоматически.

## Проверки и команды

```bash
python3 -m unittest discover -s backend/features/agent_change_dispatch -p 'test_*.py'
npm test -- --runInBand src/components/EstimateSelectedToolbar.test.jsx
npm run status:agent-job-worker
```

Проверка состояния worker выполняется в транзакции только для чтения и не
показывает содержимое заданий.

## Границы безопасности

- Всегда: точная компания, проверенный тип события, идемпотентность, запуск
  после commit, отдельная короткая транзакция очереди.
- Только после отдельного решения пользователя: новые автоматически
  запускаемые события, модельные обработчики, внешние уведомления.
- Никогда автоматически: платежи, штрафы, утверждение документов, списание или
  перемещение материалов, отправка поставщику, исправление бизнес-данных.
- Ошибка очереди возвращает ограниченный код состояния и не раскрывает
  реквизиты соединения, payload или внутренний идентификатор повторения.

## Критерии завершения A6

- активация сметы ставит ровно одно задание после commit;
- worker обрабатывает только разрешённые типы и не вызывает модель;
- очередь не содержит ожидающих, зависших, ошибочных или неизвестных заданий;
- контрольное задание `10` завершено успешно за одну попытку;
- история, экспорт и редкие команды скрыты в меню «Ещё»;
- автоматическая проверка не меняет платежи, склад, сметы и внешние каналы.

## Производственная проверка 2026-10-01

На рабочем сервере HTTP-сервис и `stroyka-agent-job-worker` активны. Отчёт
готовности вернул `readyForWorker=true`: всего `63` задания, все `63` успешны,
ожидающих, выполняющихся, просроченных, ошибочных и неизвестных типов — `0`.
Задание `10` имеет статус `succeeded`, одну попытку и результат режима
`deterministic_read_only`. Флаги `AGENT_CHANGE_DISPATCH_*` в HTTP-сервисе
отсутствуют, поэтому новые типы автозапуска нельзя включить случайно.

Защищённый smoke нельзя повторить из неинтерактивного SSH без текущего кода
2FA. Его более раннее успешное прохождение и ввод worker в эксплуатацию
зафиксированы в `docs/agent-job-worker-production.md`; текущая проверка
ограничилась состоянием сервисов, схемы и очереди.
