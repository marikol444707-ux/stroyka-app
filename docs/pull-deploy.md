# Выкладка сайта с сервера

Раньше GitHub сам заходил на сервер по SSH и запускал обновление. До этого сервера он достучаться не может, поэтому теперь сервер сам забирает новый код.

Каждые пять минут сервер смотрит ветку `main`. Если там тот же коммит, что уже работает, он ничего не делает. Если коммит новый и проверка CI зелёная, запускается обычный `deploy.sh`. Потом сайт проверяется по адресу https://stroyka26.pro/health. Если новая версия не ответила, сервер возвращает предыдущий коммит.

Пока проверка CI ещё идёт, выкладка ждёт следующего раза. Если проверка красная или выкладка сорвалась, этот коммит больше не пробуется снова. Следующий коммит в `main` пробуется как обычно.

## Установить один раз

На сервере, после того как это изменение уже попало в `main`:

```bash
cd /var/www/stroyka-app && git pull --ff-only && sudo bash scripts/install-pull-deploy.sh
```

Команда безопасна для повторного запуска.

## Журнал

```bash
journalctl -u stroyka-pull-deploy -n 50
```

Удачная выкладка заканчивается строкой `Выложено:` и номером коммита. Пустой журнал между запусками означает, что новый коммит не появлялся.

## Поставить на паузу

```bash
sudo systemctl disable --now stroyka-pull-deploy.timer
```

Сайт остаётся как есть. Снова включить:

```bash
sudo systemctl enable --now stroyka-pull-deploy.timer
```

Убрать таймер совсем:

```bash
cd /var/www/stroyka-app && sudo bash scripts/install-pull-deploy.sh --uninstall
```

## Если один коммит нужно попробовать ещё раз

Так бывает, когда сеть моргнула во время сборки, а следующий коммит ещё не готов. Сервер запомнил неудачный коммит здесь: `/var/lib/stroyka-deploy/failed-sha`.

```bash
sudo rm -f /var/lib/stroyka-deploy/failed-sha
```

На следующем запуске, примерно через пять минут, этот коммит попробуют снова. Можно не ждать и выполнить:

```bash
sudo systemctl start stroyka-pull-deploy.service
```

Токен GitHub не нужен: репозиторий открытый. Если когда-нибудь GitHub начнёт отвечать «слишком много запросов», root может положить одну строку `GITHUB_TOKEN=...` в файл `/etc/stroyka/pull-deploy.env` с правами `600`. Скрипт сам его прочитает и в журнал не выведет. Без файла всё работает как обычно.
