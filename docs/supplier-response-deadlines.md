# P6 — сроки ответа на КП и внимание поставщика

Согласовано: автоматически следующий будний день (Пн–Пт, праздники не учитываются),
то же время по Europe/Moscow. Заказчик может изменить срок перед запросом КП.
Срок относится к конкретному созданному КП, хранится как TIMESTAMPTZ; повтор
request-kp не продлевает уже существующие предложения. Старые записи без срока
остаются без срока. Просрочка не блокирует возможность ответить.

Сегодня/Просрочено относятся только к КП в ожидании ответа. Ответ, отказ или
отзыв снимает необходимость ответа. Счётчики считают заявки, не дубли КП.
Ждём заказчика: есть отправленное КП. Можно готовить: выбранное КП без уже
созданной отгрузки, выполнение действующего условия оплаты; это информационная
карточка, сервер повторно проверяет разрешение при отгрузке. Счета и оплаты не
изменяются. Карточки фильтруют полную доступную выборку и CSV.

План: pure policy + тесты времени; сохранение срока при создании КП + PG; поле
формы и передача API; отображение срока и фильтры/карточки; браузер; миграция,
backup/release. Миграция добавляет nullable колонку, без backfill. Rollback к
предыдущему коду сохраняет новую колонку и значения, downgrade запрещён при данных.

## Проверки

- Pure backend policy: 2 PASS; отдельная PostgreSQL-проверка: 3 PASS (реальный
  HTTP, сохранение/повтор/rollback неверного срока, миграция и защита downgrade).
- Общий backend: 3791 tests; 3 ошибки из-за отсутствия новой зависимости
  в AST-стенде, 653 skipped. Стенд обновлён; все 12 его сценариев + 2 policy PASS.
- Общий frontend: 1173 PASS, один тест не совпал с пробелом в доступном имени
  кнопки; исправлено ожидание. Финальные затронутые suites: 14 PASS.
  Отдельные deadline/payment boundary cases PASS. Production build PASS.
- Browser: 25 заявок; 6 overdue, 6 today; клики фильтруют строки; Москва явно
  обозначена; mobile320 без overflow. В форме директора default следующий
  понедельник, ручное изменение поля работает. Реальные внешние письма не отправлялись.
- Известный baseline: supplier получает403 фонового company-material-aliases,
  landing facade preload warning. Новых JavaScript errors нет.

Ревью: срок обновляется только у ids, возвращённых созданием новых предложений,
в той же транзакции и с request/company условиями. Авторизация и блокировка
заявки предшествуют записи. Дата не входит в supplier-editable fields.
Readiness — информационная оценка по загруженным счетам/отгрузкам, сервер
по-прежнему проверяет отгрузку самостоятельно. Расчёты/записи оплат не изменены.
