## Подтверждённая ошибка

Обновление истории, фильтр и ошибка загрузки закрывали заполненный возврат.
Другая карточка возврата или отправка тоже стирала ввод. Пять новых тестов
упали до исправления. Теперь форма хранит исходное распределение и ввод до
явной отмены, подтверждённого результата или прекращения доступа.
Для нового POST нужен свежий источник; количество проверяется по его текущему
остатку. Неизвестный результат прежнего POST по-прежнему разрешает только
существующий безопасный повтор с неизменными requestId и телом команды.

## Ограничения и установка

- Неотправленный черновик остаётся в памяти панели. Закрытие вкладки,
  перезагрузка всей страницы или уход из раздела могут его уничтожить.
- Проверка с PostgreSQL ограничена складским модулем. Полный App, настоящий
  вход/2FA, отдельные экраны материалов объекта, финансовые документы и журнал
  качества с включённым feature flag здесь не проверялись. Схема стенда —
  существующая минимальная тестовая fixture, не копия рабочей базы и не полный
  прогон миграций. Проверка ролей через API не означает браузерную проверку
  каждого кабинета.
- Предыдущая авторизованная браузерная приёмка серверного пакета `5301551`
  остаётся неподтверждённой. Известные инструментальные блокеры описаны в
  `warehouse-receipt-report.md`; локальный стенд их не закрывает. Резервы,
  staging и маркеры `verified.json`/`deployed.json` не менялись.
- `warehouse-return-draft.patch` содержит только этот блок поверх `2415e23`.
  `warehouse-movement-drafts.patch` содержит **все три локальные доработки**
  (приёмка, отправка, возврат) поверх установленной базы `5301551`. Это
  альтернативы для разных баз, а не два последовательных патча. Прежние
  патчи смет, кабинета мастера и складских блоков сохранены без изменений.
- Нужна только сборка/публикация frontend с действующими серверными флагами;
  миграция и изменение backend не требуются. После установки проверить
  backend, неизменность схемы, manifest/файлы и все три формы в авторизованном
  браузере. На рабочем сервере проверять ввод, обновление, фильтр и отмену,
  не создавать фиктивных складских проводок.
- Откат — предыдущие frontend manifest/public; восстановление БД не требуется.
  Очистка резервов разрешена только после всех четырёх подтверждений по
  `docs/deployment-retention.md`.
