# Пакет подключения источников JEV

Запрос пользователя: подключать источники одним пакетом, включая коммерческие
площадки и официальные закупки владельцев объектов. Код ниже не устанавливался
на сервер. **Живая проверка нового режима пока не выполнена ни для одной площадки.**

## Состояние пакета

| Источник | Что реализовано в коде | Что требуется до рабочего подключения |
|---|---|---|
| B2B-Center | Поиск, первичная карточка, публичные вложения | Живая сверка DOM, браузера и документов |
| Фабрикант | Отдельный план и URL-семейство, общий читатель карточек/вложений | Живая сверка выдачи, полей, редиректов |
| ТЭК-Торг | Отдельный план, разбор SSR __NEXT_DATA__, первичные ссылки | Живая сверка смешанного коммерческого/223 раздела |
| ЭТП ГПБ | Публичная JSON-выдача, первичные ссылки, общий читатель | Живая сверка API и первичных карточек |
| Росэлторг | Отдельный поиск без фильтра региона заказчика, первичные ссылки | Живая сверка выдачи и карточек |

Статус «код читателя есть» не означает доступность площадки или наличие закупок.

## Единое подключение

```python
from jev_agent.tender_finder.commercial.portal_reader import source_bundle
from jev_agent.tender_finder.commercial.recipes import load_recipes

# Всё ниже задаёт защищённый startup, не JSON модели.
recipes = load_recipes('/etc/jev-portals/portals.json', trusted_root='/etc/jev-portals')
sources, adapters = source_bundle(
    open_browser=reviewed_public_browser,  # async context manager, получает Source
    clock=aware_clock,
    scope=authenticated_scope,
    reviewed_recipes=recipes.factories,
    extra_sources=recipes.extra_sources,
)
```

Это одна фабрика для всех восьми существующих площадок и всех добавленных
проверенных порталов. Не нужно писать отдельный worker/очередь/Telegram-бота для
каждого сайта. Защищённый CommercialBridge использует полученные sources/adapters.
Неиспользуемые пока направления показываются как not_connected.

Browser factory создаёт отдельный credentials-free контекст для каждого Source,
применяет разрешённые домены, proxy/CA, robots/access policy и ограниченный CDP.
В production должен быть проверен реальный browser opener. Этот документ его
установку/наличие не подтверждает.

## Как переносится старый поиск

- Используются известные endpoint/URL-семейства старого кода, а не его subprocess
  и не прежние ограничения географии. Файл старого CLI не менялся.
- Фильтры customer_region/region заказчика сняты: они не доказывают место работ.
- Для GPB/Р-ТЕНДЕР/ТЭК используются первичные ссылки из проверяемых JSON/SSR форматов;
  финансовые данные и даты старых нормализаторов не переносятся в рекомендации.
- Стоимость, валюта, НДС, регион, адрес, этап, сроки, оплата, роль и требования
  устанавливаются по свежей первичной карточке и документам общей evidence policy.
- В том числе не переносится старое предположение «дата без зоны = МСК».
- Запрошенные виды работ и слова исключения проверяются на первичных сведениях.
- Первые страницы, непроверенный parser и частичный охват явно показываются.
- Чужой URL, CAPTCHA, вход, ошибки и нераспознанные поля не становятся пустым успехом.
- На источник — до 180 секунд начала чтений и 40 карточек/страниц; после 600 секунд
  пакет не начинает оставшиеся источники. Их статус not_checked_due_budget,
  а не «сайт недоступен». Уже начатый источник имеет собственные ограничения.

## Защищённые рецепты новых порталов

Формат файла — JSON, не Python/JavaScript. Пример **синтетический, не адрес Tender.Pro**:

```json
{
  "format": 1,
  "portals": [{
    "source_id": "tenderpro",
    "hosts": ["owner.example"],
    "listings": ["https://owner.example/procurement"],
    "reviewer_subject": "operator-reviewer",
    "review_evidence_url": "https://owner.example/about",
    "notice_path": "/notice.html",
    "notice_query_key": "notice_id"
  }]
}
```

Для пути вида /notices/123 вместо query-key задаётся notice_path=/notices и ключ
notice_query_key пропускается. Регулярное выражение не принимается из JSON: путь
экранируется кодом, идентификатор имеет фиксированный ограниченный формат.
Если проверен параметр поиска, search_query_parameter добавляет только закодированные
названия видов работ и двух регионов. Без него читатель просматривает явно заданные
публичные страницы, не утверждая, что фильтры применены на стороне сайта.

Новый заказчик вне каталога требует явных name/category (owner/agriculture/research).
Дополнительные Source используются тем же контрактом, tenant isolation и отчётом.
Переписать native reader или переименовать другой источник таким файлом нельзя.
Production файл root:root 0600, каталог root:root 0700, без симлинков/хардлинков.
Настройки модели и переменные окружения не являются источником конфигурации.

Это проверка настройки портала, а не подтверждение прямого договора. Роль стороны
и полномочия всё равно требуют независимых доказательств. Регистрация, вход,
покупка доступа, отправка документов/предложений и установка служб не выполняются.

## Доступ к сайтам в рабочей среде

31.10.2026 пользователь опубликовал сетевые настройки среды. Применённая ревизия 4
разрешает известные хосты площадок и Google/Bing. Это настройка среды Codex;
она не устанавливает JEV на Timeweb и не публикует публичный сайт.

Живой read-only прогон 31.10.2026, около 23:22 МСК (одна страница на источник):

| Источник | Наблюдение | Что ещё требуется |
| --- | --- | --- |
| B2B-Center | robots.txt запрещает выбранный `/app/next/market-search?` | Разрешённый владельцем способ доступа; запрещённый путь не обходится |
| Р-ТЕНДЕР | HTTP 200, JSON: count=0, totalCount=0, list=[] по запросу «кровля» | Другие запросы и реальная первичная карточка; это не полный поиск |
| Торги Федерации | Страница — оболочка SPA; отдельная проверка публичного API в 23:25 МСК: HTTP 200 JSON, total_count=0 по «кровля» | Подключить этот формат к новому читателю и проверить реальную первичную карточку |
| Tender.Pro | В повторном прогоне HTTP 503; ранее получена страница Testing | Доступность и разрешённый способ чтения; challenge не решается |
| Росэлторг, Сбер А, ЭТП ГПБ, Фабрикант | robots.txt недоступен, HTTP 503 от сетевого тракта | Повторная проверка доступа; списки не читались |
| ТЭК-Торг | robots.txt возвращает 307 на тот же URL | Исправный ответ политики доступа; список не читался |

Это подтверждение доступности отдельных ответов, **не приёмка восьми подключений**.
Ozon, агрохолдинги и другие владельцы пока требуют проверки официальных хостов,
путей закупок и первичных карточек. Домены заказчиков в сетевые правила ещё не добавлены.

Общий пакет теперь проверяет robots.txt до запуска браузера, каждой навигации
и скачивания документа. Запрет обозначается `robots_disallow`, неизвестная политика
при сетевой ошибке/5xx/неверном ответе — `policy_not_verified`. Эти статусы не означают
«нет закупок» или «нет документа». Действует короткий кэш; разрешение не переносится
на другой хост. Идентичность агента не меняется для обхода запрета.

Хостовый Chromium в этой среде не запускается с исправной песочницей. Параметр
`--no-sandbox` для просмотра живых сайтов не использовался. Поэтому чтение
отрисованных первичных карточек и сквозной ответ в Telegram пока не подтверждены.

## Проверки

```bash
python3 -B -m unittest -v jev_agent.tender_finder.commercial.test_platforms jev_agent.tender_finder.commercial.test_recipes
```

Тесты синтетические. Проверяют пакет восьми площадок, подключение одиннадцати
именованных новых порталов данными в одном вызове (в сумме 19), SSR/JSON варианты,
сохранность первичных фактов, неизвестные номера, ограничения и private config.
Это не девятнадцать проверенных живых подключений.
