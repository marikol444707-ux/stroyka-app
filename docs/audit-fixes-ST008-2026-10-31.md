## Поведение

- Складской поиск передаёт точный material/tool ID и companyId. Материал открывается единственной найденной строкой в существующем представлении объекта; инструмент — в существующем списке инструментов. Одноимённая позиция не подставляется. Доступно снятие фокуса «Показать все позиции».
- Общий контракт ссылок: `view`, `appCompanyId`, `appProjectId`, `projectTab`, `entityType`, `entityId`. Поддержанные типы: material/tool/estimate/document; document означает запись существующего реестра документов объекта. Произвольный тип не принимается. Ссылка документа требует project ID.
- Компания из URL не является полномочием и не переключается автоматически. Другой owner, неизвестный ID или ещё не загруженная запись дают явное состояние недоступности/ожидания. При смене компании старый выбранный объект не восстанавливается из URL как новый.
- Переход из объекта в смету теперь использует этот контракт. У сметы проверяется company и объект; legacy projectName допускается только при однозначном соответствии внутри компании. Возврат сохраняет объект и вкладку. Поздний ответ загрузки не возвращает закрытую смету и не перезаписывает список другой компании; ответ с отличающимся owner отвергается.
- В реестре есть адресуемая ссылка на конкретный документ. Список/основания договоров в этой панели отбираются по companyId/projectId, а не только имени объекта. Существующие защищённые URL сканов/файлов не преобразовывались.
- Browser back/popstate, снятие фокуса и обычный переход обновляют подписчиков. Обычный переход снимает entity target, сохраняя контекст объекта.

## Что ещё нужно и где требуется решение

**Приёмка/миграции, а не пропущенные правки этого перехода:** реальный browser/mobile/все роли ST-002–010, ST-015–017; PostgreSQL, полный bootstrap и миграции 0103–0108 ST-001, ST-010, ST-012, ST-021–038. Нужны owner reconciliation старых записей, контроль persisted state и concurrency. В этом продолжении эти проверки не исполнялись; прежний запрещённый запуск не повторялся.

**Реальные недоработки/решения:** ST-013 — применение черновика запуска остаётся отсутствующим, по прямому указанию не реализовано. ST-014 — не утверждена матрица зрелости функций/ролей/флагов. ST-018–019 — исторические недостатки тестового fixture/AI adapter, а не готовые проверки с PASS. ST-020 — контракт 404/403 требует согласования; не менялся.

**Граница ST-008, требующая продуктового решения:** существующий режим `inventoryReconciliationEnabled` направляет прораба из всего склада в инвентаризацию. Для entity-ссылки теперь показано явное ограничение вместо тихого открытия другого экрана. Разрешать этому режиму отдельные material/tool карточки без решения о доступности модулей не стал. Флаг не менялся. В обычном складском режиме material/tool переход реализован. Это ограничение существующей ролевой маршрутизации, не серверное доказательство запрета доступа.

Не введён универсальный навигатор для всех накладных, КС, актов, платежей и произвольных файлов: у них разные существующие экраны/права/версии. Текущий контракт закрывает смету и документ реестра; распространение на остальные типы требует перечня целевых экранов, а не угадывания. Исходный ST-008 не доказывал неисправность каждого такого типа.

Это не завершение полного аудита, не принятие полной изоляции компаний и не разрешение на выпуск.
