# Единые реквизиты компании

## Назначение

`company_requisites` — единственный изменяемый источник юридических и банковских
реквизитов компании-клиента. Таблица `companies` остаётся краткой платформенной
карточкой для списков, тарифа, лимитов и контакта; она не должна использоваться
как полный источник данных для договоров, счетов, актов и печатных форм.

## Поток данных

1. Владелец платформы создаёт клиента и вводит либо распознаёт реквизиты.
2. `POST /system/companies` в одной транзакции создаёт аккаунт, компанию,
   `company_requisites` и приглашение директору. Ошибка любого шага откатывает
   все созданные записи.
3. Клиент видит те же данные в разделе `Настройки → Реквизиты компании` и может
   их уточнить через `POST /company-requisites` в рамках выбранной компании.
4. После загрузки приложения ответ `GET /company-requisites` одновременно
   заполняет форму настроек и объект `companyRequisites`, который передаётся во
   все клиентские генераторы документов.
5. Платформенные счета и акты читают `company_requisites` напрямую. Общая
   карточка `companies` применяется только как fallback для старых записей.
6. При создании платформенного договора реквизиты преобразуются в неизменяемый
   снимок стороны договора. Последующее редактирование настроек не меняет уже
   выпущенный договор.

## Канонические поля

- наименование: `fullName`, `shortName`;
- регистрация: `inn`, `kpp`, `ogrn` (ОГРН или ОГРНИП);
- адреса: `legalAddress`, `actualAddress`;
- контакты: `phone`, `email`;
- подписант: `directorName`, `directorPosition`, `basis`;
- банк: `bankName`, `bik`, `rs`, `ks`.

Сервер нормализует пробелы, email и цифровые поля. Идентификатор компании
берётся только из проверенного сервером контекста, а не из произвольного поля
запроса пользователя.

## Правило для новых документов

Любой новый генератор документа должен принимать `companyRequisites` либо
читать `company_requisites` по серверно выбранному `company_id`. Название из
`companies.name` допустимо лишь как отображаемый fallback. Нельзя повторно
создавать отдельную форму реквизитов внутри нового модуля.

Для юридически значимых документов требуется снимок реквизитов на момент
выпуска. Для оперативных печатных форм используются текущие реквизиты из
настроек.
