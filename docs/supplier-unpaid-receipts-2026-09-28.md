# Поставка до первого платежа

Локальный этап после `83bfb6d6`, без установки на сервер. Новая миграция не нужна.
Дополнительный флаг `SUPPLIER_UNPAID_RECEIPTS_ENABLED=1` по умолчанию выключен.
Также нужны существующие флаги частичной приёмки, принадлежности поставок и
журнала качества; для последующей оплаты — журнал оплат.

Авторизованная отгрузка/приёмка может зарегистрировать исходный неоплаченный счёт
в журнале с нулевой начальной оплатой. Запись выполняется в той же транзакции;
ошибка отгрузки откатывает и регистрацию. Денежная операция не создаётся.
Материал принимается обычным способом, накладная связана с исходным счётом через
подтверждённые строки и не создаёт второй долг. Первый платёж позже использует
эту же запись, в том числе если он поступил между отгрузкой и приёмкой.

Допускаются только утверждённые новые счета с сохранёнными строками и проверенной
версией договора, без старой накладной и без исторических оплат. Плательщик должен
совпадать с компанией-владельцем. Другой плательщик требует отдельной доработки
допуска; его нельзя автоматически подменять владельцем. НДС и старые счета
остаются отдельным этапом. Обязательная предоплата по договору продолжает
блокировать отгрузку до её поступления.

Проверки выполняются на изолированном PostgreSQL через настоящие HTTP-маршруты:
две частичные приёмки до оплаты, повторная приёмка, первый платёж после приёмки
и до неё, отказ чужой компании, обязательная предоплата, откат неудачной отгрузки,
флаг по умолчанию, отказ импорта старой оплаты и неутверждённого счёта.

Все 14 проверок прежней частичной приёмки прошли:
`/tmp/unpaid-receipts-verified.log`. Интерфейс не менялся; браузерная сквозная
проверка полного финансового выпуска остаётся обязательной. Предупреждения
AI-контроля в тестовой fixture не означают, что этот подсистемный контроль проверен.
