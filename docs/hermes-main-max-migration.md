# Hermes: перенос с MAX

Перенос сохраняет образ Hermes, каталог данных, токены, память, историю,
доступы и существующие отключённые задания. Telegram временно выключается через
`platforms.telegram.enabled: false`: основной сервер пока не устанавливает HTTPS
соединение с Telegram API. Токен и история Telegram сохраняются.

Для установленного пользовательского адаптера MAX добавлен атомарно сохраняемый
курсор polling, привязанный к идентификатору бота. Исправление применяется только
к проверенному SHA256 адаптера. Маркер сохраняется после передачи всей пачки
обработчику. Это не гарантия exactly-once при аварии во время ответа модели;
плановый перенос требует завершения активных ответов и корректной остановки.

Проверки до установки:

```
python3 -B -m unittest ops.hermes_max.test_poll_cursor
python3 -B -m ops.hermes_max.verify_adapter /private/path/to/original/adapter.py
```

Порядок переключения:

1. Снять исходное состояние контейнеров и служб, сделать предварительную копию.
2. Проверить доступ к MAX и модели с основного сервера без чтения очереди сообщений.
3. Дождаться отсутствия активных запросов, остановить старый шлюз и его входящие
   задания. Отключить автоматический запуск старого экземпляра.
4. Досинхронизировать данные остановленного шлюза, проверить хеши и SQLite.
   Сохранить устаревшие данные основного сервера отдельно для отката.
5. Перенести последний подтверждённый маркер из журнала старого шлюза,
   установить исправление и выключить Telegram в копии конфигурации.
6. Переключить JEV с межсерверной передачи на локальные службы. Только один
   набор рабочих процессов может выполнять задания; сохранить очереди и ключи.
7. Запустить основной шлюз, проверить MAX, модель, память, разрешения и JEV.
   Пользователь проверяет один ответ в MAX и сведения из прежней памяти.

Откат: остановить основной шлюз и обработчики до запуска старых; перенести его
актуальные данные и курсор обратно на тестовый сервер, восстановить исходную
настройку Telegram и исходные службы JEV. Не откатывать историю к старой копии.
Если новый шлюз ещё не принимал сообщения, достаточно сохранённой исходной копии.

До успешных проверок материалы отката сохраняются. После отдельных проверок
backend, базы, frontend, браузера и подтверждения MAX удалить временные копии
по `deployment-retention.md`. Удаление тестового VPS требует отдельной проверки
оставшихся зависимостей; остановка контейнера сама по себе оплату VPS не прекращает.
