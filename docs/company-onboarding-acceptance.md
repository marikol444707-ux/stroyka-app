## Что изменено

- `/users`: выбранная компания определяет доступ; общий аккаунт можно отключить или
  переназначить в одной компании, сохранив остальные членства. Имя, пароль и 2FA
  общего аккаунта не изменяются руководителем отдельной компании. Служебные роли
  платформы, аккаунта и поставщика исключены из кадрового API и формы.
- Приглашения сотрудников: компания/аккаунт/автор берутся с сервера, проекты
  проверяются внутри компании. Чужие и служебные коды недоступны через этот раздел.
  Для проектных ролей форма предлагает объект и необходимые пакеты работ.
- Регистрация: точное владение приглашением, активность компании, объект, явное
  членство и одноразовое погашение кода. Старые коды без компании не угадывают
  владельца по названию. MAX использует те же правила и транзакцию.
- Положительные `max_projects`/`max_users` исполняются под блокировкой компании.
  Считаются активные неархивные объекты и уникальные активные аккаунты с доступом.
  Уже активный пользователь не расходует второе место при смене роли. Пустой/нулевой
  лимит сохраняет прежнее значение «без ограничения». Новые проверки не отключают
  существующих пользователей и не удаляют объекты при превышении старого лимита.
- Лимиты действуют в `/projects`, создании объекта из CRM, `/users`, доступе из
  `/staff`, обычной и MAX-регистрации. Отказ откатывает весь связанный запрос.
- Форма объекта направляет к приглашению заказчика с выбором объекта; больше не
  создаёт второй аккаунт отдельной командой и не показывает пароль в уведомлении.
- Новая форма пользователей и приглашений не выходит за ширину 390px.
